# キップテン

切符の4桁で 10 を作る、日替わりパズル。

毎日 0 時（日本時間）に、全員に同じ番号の切符が出ます。4つの数字を全部1回ずつ使い、＋−×÷と括弧で 10 を作ります。解けたら入鋏が入り、ほかの解き方も探せます（全解探し）。解いた番号は硬券図鑑（0000〜9999）に集まります。

- 設計：ブランチ `claude/dazzling-planck-qofymj` の「アプリ4案_設計書_第2弾.md」の「案4 キップテン」と「共通の技術方針」
- サーバー・アカウントなし。ゲームは通信しないで動きます（通信するのは広告とストアだけ）
- ストアへの提出手順：[docs/STORE_SETUP.md](docs/STORE_SETUP.md)　プライバシーポリシー：[docs/PRIVACY.md](docs/PRIVACY.md)　掲載文と画像：[store/](store/)
- 実在の鉄道事業者名・駅名・地紋は使っていません。硬券のデザインと地紋（波線）はすべて自作です

### 正規化（「本質的に違う解」の数え方）

- 足し算・引き算の連なりは「足す項の集まり」と「引く項の集まり」、掛け算・割り算の連なりは「掛ける因数の集まり」と「割る因数の集まり」にまとめ、集まりの中を並べ替えて比べます
- これで 3 + 7 と 7 + 3、(1 + 2) + 7 と 1 + (2 + 7)、9 − (3 − 4) と 9 + 4 − 3、8 ÷ (4 ÷ 5) と 8 × 5 ÷ 4 が同じ解になります
- 分配法則（2 × (3 + 2) と 2 × 3 + 2 × 2）や、＋0・×1 の付け方の違いはまとめません（別の解）
- 解ごとの「分数経由」は、その解のどの書き方でも途中に整数でない値が出るときに付けます

### 出題の難易度帯

| 曜日 | 帯 | 条件 | 番号の数 |
| --- | --- | --- | --- |
| 月 | やさしい | 解が7通り以上 | 3,050 |
| 火・水・日 | ふつう | 解が3〜6通り | 2,905 |
| 木・土 | むずかしい | 解が1〜2通り（分数なしで解ける） | 2,138 |
| 金 | 分数の難問 | どの解も分数を経由する | 54 |

通し番号 No.1 は 2026年11月1日です。過去365日に出た番号は出しません。あわせて、同じ数字の組み合わせ（7168 と 6781 など）もなるべく30日は空けます（分数の難問は4組み合わせしかないので、金曜は空けられないときがあります）。

## 設計書と違う判断

| 設計書 | この実装 | 理由 |
| --- | --- | --- |
| 永続化は drift（SQLite） | `shared_preferences` に JSON | 依頼の「hisokagi のパッケージの選び方に合わせる」に従った。記録は最大でも 8,147 番号＋日ごとの記録で小さい。テーブルの形（solved / play_log）は設計書のまま |
| 共通基盤 ookura_design・ookura_a11y・ookura_consent・ookura_meta を使う | 使っていない | リポジトリに無い。広告が仮の実装なので、同意（ookura_consent）はまだ要らない |
| ookura_daily をそのまま使う | `lib/daily/` に同じ形で作った | リポジトリに `packages/ookura_daily` が無かった（依頼の指示どおり） |
| 記念日の例「1月1日は 0101」 | 元日は西暦4桁（2027 など）を出す | 0101 には解がない（0・1・0・1 では最大でも 2）。設計書の「解がある場合」に従い、元日は年号の切符にした。年号にも解がない年（2030・2031・2033 など）はふつうの出題 |
| 記念日の例「鉄道の日は 1001」 | 表に入れていない | 1001 にも 1014 にも解がない |
| 図鑑は「百の位ごと（10ページ）」に「完」 | 千の位ごと（0千番台〜9千番台の10ページ） | 0000〜9999 を10ページに分けると1ページは1,000番号なので、千の位で分けた |
| 曜日の難易度帯は月（易）と金（分数）だけ指定 | 上の表のとおり全曜日に割り当てた | 指定のない曜日を決める必要があった |
| 同じ番号を過去1年避ける | それに加えて、同じ組み合わせもなるべく30日空ける | 7168 と 6781 のように、並べ替えただけの番号が近い日に続くと同じ問題になるため |
| 活版風の無料フォント | 端末の標準書体 | フォントのライセンス確認が済んでいない |
| iPhone・iPad の両方 | iOS は iPhone のみ（iPad では iPhone 版として動く）。縦向きのみ | 画面を縦向きの電話の大きさで作っている。iPad 向けの画面とスクリーンショットは初版では用意しない |
| 共通基盤 ookura_consent で同意を取る | アプリ内（`lib/monetize/ad_service.dart`）で UMP を呼ぶ | ookura_consent がリポジトリに無い。ひそかぎと同じ書き方にした |
| 通知は1日1回 | 7日分を先に予約し、アプリを開くたびに予約し直す | サーバーなしで日替わりの番号を文面に入れるため。開かない日が7日続くと通知も止まる（しつこくしない） |
