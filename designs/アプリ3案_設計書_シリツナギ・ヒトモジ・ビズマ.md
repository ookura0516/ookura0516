### 共通の技術方針

- Flutter で iOS・Android を1つのコードから作る。ひそかぎと同じく共通パッケージ ookura\_core を使う
- データは端末内だけに保存し、アカウント登録はなし。サーバー費はかからない
- 課金は in\_app\_purchase の買い切り。広告を入れるのはシリツナギだけで、子どもも使うビズマと日記のヒトモジには入れない
- ウィジェットは home\_widget を使い、iOS は WidgetKit、Android は App Widget を各OSのコードで書く
- 資料の「iOS先行がデファクト」に合わせて iOS を先に出し、Android は Google Play のクローズドテスト（12人×14日）を並行で始める
- 同じアカウントから似たアプリが続くと App Store のスパム判定（ガイドライン4.3）に当たりやすい。3案は見た目と用途をはっきり分けておく

## シリツナギ（仮）：しりとり一筆書きパズル

盤面に並んだ単語カードを、しりとりがつながる順に隣へ隣へと指でなぞり、全部のカードを1本の線で通す日替わりパズル。資料の「既知ルール＋一ひねり」「日本語ネタは国内で独占できる」「デイリー1問と結果画像のシェア」をそのまま形にした案で、一文で説明できる。

### 勝ち筋

- しりとりは説明がいらない。一筆書きの制約を足すだけで「知っているのに新しい」問題になる（Meowdoku! の型）
- 全員が同じ日に同じ問題を解くので、結果の投稿が「今日の話題」になる
- 配信では視聴者が「次は『め』から！」と同時に口を出せる。資料が配信者起点の条件に挙げた「視聴者が答えられる構造」を満たす
- 問題は単語リストから自動で作れるので、作問の手間がほぼかからない

### ルール

1. 盤面に6〜16枚のカードが並ぶ。スタートのカードには印がある
2. 縦・横・斜めに隣り合うカードへだけ進める。次のカードは、前の単語の最後の文字で始まっていなければならない
3. 全部のカードを一度ずつ通ったらクリア。答えは必ず1通りになるように作る
4. 各カードの左上に「頭の文字」、右下に「おしりの文字」を小さく表示する。小さい字は大きく（ゃ→や）、伸ばす音は前の文字の母音（コーヒー→い）と決め、読み方で揉めないようにする
5. 曜日で難しさが上がる。月曜は2×3の6枚、日曜は4×4の16枚で、同じ頭文字のカードが複数あって迷いやすい

月曜の盤面の例（スタートは「すいか」）：

|  | 1列 | 2列 | 3列 |
| --- | --- | --- | --- |
| 1行 | すいか（スタート） | かめ | めだか |
| 2行 | らっぱ | さくら | かさ |

答えは すいか → かめ → めだか → かさ → さくら → らっぱ。「すいか」の次は「かめ」と「かさ」の両方が候補だが、隣り合うのは「かめ」だけなので答えが1つに決まる。

### 画面構成

| 画面 | 内容 |
| --- | --- |
| 今日の1問 | 盤面、経過時間、ヒントボタン。指を離しても線は残り、戻るには線をたどり直す |
| クリア | 答えを伏せた結果画像（線の形・時間・ヒント数・通し番号）と、つないだ単語の一覧 |
| 過去問 | カレンダーから過去の問題を解く。無料は直近7日分 |
| 配信モード | 横画面で文字を大きくし、時間表示を消せる。「配信・動画投稿は申請不要」とアプリ内とストアに明記する |
| 記録 | 連続日数、曜日別の平均時間、解いた問題数 |

### 拡散と継続の設計

- 結果画像は答えが分からないように単語を伏せ、線の形だけを見せる。「シリツナギ #42 日曜 2:31 ヒント0」の文字も付ける
- シェア文面にはストアのリンクを入れず、画像とアプリ名だけにする（資料：リンク付き投稿は閲覧が94%少ない）
- ホーム画面の小さなウィジェットに「今日は『り』から始まる」と連続日数を出す。通知は1日1回、最初はオフ
- 季節のテーマ盤を混ぜる（秋の味覚、お正月、都道府県など）。連休初日は特大盤を出す
- 連続日数が切れそうなときは、動画広告1本で前日分を解ける救済を用意する（資料：Duolingo のストリーク復活）

### 収益化

- バナー広告をクリア画面と過去問一覧に出す。解いている最中の画面には出さない
- ヒント（次の1枚を光らせる）は1日1回まで無料、それ以上は動画広告
- 「シリツナギパス」¥480 買い切り：広告削除、過去問すべて、ヒント無制限、テーマ盤のパック

### データと技術

- 単語リスト：小学生でも分かる名詞を約3,000語、自前で作り人の目で確認する。既存の辞書データはライセンスの条件（表示義務や継承）が付くので使わない
- 問題の作り方：単語同士のつながりをグラフにして枚数分の道を探し、盤面に隣り合うよう配置する。その後、総当たりで解が1通りしかないことを確かめる。16枚までなら端末でも一瞬で解ける
- 問題は2年分を事前に作ってJSONにし、アプリに60日分を同梱する。残りはアオシオリと同じく jsDelivr から配信し、審査なしで差し替えられるようにする
- 日付は日本時間0時で切り替え、端末の時計を戻して先の問題を解くのは許す（連続日数には数えない）
- 広告は google\_mobile\_ads、ウィジェットは home\_widget

### リスクと対策

| リスク | 対策 |
| --- | --- |
| 真似が速い（資料：矢印脱出は同じ月に3本並んだ） | 単語の質と曜日ごとの難しさの設計で差を付ける。通し番号と連続日数で早く来た人を囲う |
| 読み方の揉め事（「こうじょう」は「う」か「よ」か） | 頭とおしりの文字をカードに印字し、迷う単語はリストから外す |
| 不適切な語や特定の商品名が混ざる | 単語リストは人の目で確認し、固有名詞は入れない |
| 一度解いたら終わりで飽きられる | 毎日の新しい問題、曜日で変わる難しさ、季節のテーマ盤 |

## ヒトモジ（仮）：漢字1文字の日記×ウィジェット

毎晩「今日をひと文字で」漢字を1つだけ書く日記。書いた字は毛筆風の書体で半紙に載り、ホーム画面のウィジェットにその月の字が並んでいく。資料が非ゲームの最優先に挙げた「ライフスタイル記録×ウィジェット」に、「結果シェア」と「季節連動」を重ねた案。

### 勝ち筋

- 入力は1文字なので、日記が続かない人でも5秒で終わる。資料の「毎日の用事がある」を最小の手間で作れる
- 字が並んだウィジェットそのものが見た目によく、画像1枚で伝わる。Oshibana のような「ウィジェット中心・口コミで広がる」型を狙える
- 毎年12月12日（漢字の日）に年の漢字が発表され、全国が「自分の一字」を考える日がある。年末の振り返りと正月の書き初めで、毎年同じ時期に話題になれる
- 日本語の漢字が主役なので、海外の日記アプリと競わない

### 主要機能と画面

| 画面・機能 | 内容 |
| --- | --- |
| 今日の一字 | 漢字1文字を入力。思いつかないときは「嬉・疲・雨・食」など気分別の候補から選ぶ。任意で30字までの一言メモ |
| 月の一覧 | カレンダーにその日の字が並ぶ。字を押すとメモが出る |
| 年の一覧 | 365字を織物のように並べた1枚。よく使った字・部首の集計 |
| 一年の一字 | 12月に開く振り返り。よく使った字と月ごとの字を見ながら一字を選び、理由を書いてポスター画像にする |
| 書き初め | 1月に「今年の抱負を一字で」。年末に自分の一字と並べて見返せる |
| 今すぐ一字 | 初日から使える単発モード。記録がなくても「今年を一字で」のポスターを作れるので、初年度の12月にも間に合う |

### ウィジェット

| 大きさ | 表示 |
| --- | --- |
| 小 | 今日の字。まだなら「今日をひと文字で」と空いた半紙 |
| 中 | 今週の7字 |
| 大 | 今月のカレンダー。書いた日だけ字が埋まる |
| ロック画面（iOS） | 今日の字 |

ウィジェットを押すとそのまま入力画面が開く。資料にある「ウィジェットで便利になって開かれなくなった」失敗を避けるため、入力だけは必ずアプリで行う。

### 拡散と継続の設計

- 月末に「10月のわたし」の一覧画像を作る。メモは初期設定で画像に入れず、字だけを見せる
- 年に4回の山を作る：12月（一年の一字）、1月（書き初め）、3月（年度末・卒業を一字で）、誕生日（この1年を一字で）
- 連続日数は表示するが、書き忘れた日は2日前まで後から書ける。途切れを責めない
- 通知は1日1回、初期は21時30分。その日に書いていれば送らない
- 学校・部活で「今月の字を見せ合う」使い方を想定し、一覧画像はストーリーズ用（9:16）と正方形の2種類を用意する

### 収益化

日記に広告は合わないので入れない。無料で毎日の記録・月の一覧・小のウィジェット・一年の一字まで使える。「ヒトモジ Pro」¥600 買い切りで次を解放する。

- 中・大・ロック画面のウィジェットと紙の種類（半紙・和紙・黒板・夜）
- 書体の追加、年の一覧の高解像度画像と透かしなしのポスター
- 写真の添付、パスコードロック、バックアップの書き出しと読み込み

### データと技術

- 記録は端末内のSQLite（1日1行：日付・字・メモ・色）。ウィジェットには iOS の App Group と Android の共有領域で直近31日分だけ渡す
- 入力できるのは漢字1文字（CJK統合漢字。踊り字「々」は受け付けない）。異体字セレクタはそのまま保存する
- 書体はOFLライセンスの毛筆風フォントを同梱する。収録されていない字は Noto Serif JP で表示する
- ウィジェット本体は iOS が SwiftUI、Android が Kotlin で書く。日付が変わる0時に更新する

### リスクと対策

| リスク | 対策 |
| --- | --- |
| 「今年の漢字」は日本漢字能力検定協会の登録商標とされている（未確認） | アプリ内とストアでは「一年の一字」と呼ぶ。ストア掲載前にJ-PlatPatで確認する |
| 日記アプリは競合が多い | 1文字に限ること、字が並ぶウィジェット、年末の一字で「一言で説明できる」差を作る |
| 書く字が毎日同じになり飽きる | 気分別の候補を日替わりにし、「初めて使った字」を数えて見せる |
| メモを誤ってシェアしてしまう | シェア画像には初期設定でメモを入れない。入れるときは画像の確認画面を挟む |
| 初年度は記録が少なく「一年の一字」が作れない | 「今すぐ一字」で記録なしでもポスターを作れるようにする |

3. 3週目：買い切り、バックアップ、実機確認、ストア素材。iOSの審査を含めると、12月12日に間に合わせるには11月中に着手する必要がある

## ビズマ（仮）：写真をアイロンビーズの図案に

写真を選ぶと、5mmのアイロンビーズで作れる図案と、色ごとに必要な粒の数が出る。作るときは1色ずつ置く場所を光らせる作業ガイドになり、完成品を撮って作品帳に残せる。資料の「作品を投稿したくなる出力」（Passage、tone）と「検索語に直結する実用ツール」を1本にまとめた案で、拡散されるのは利用者が作った実物の写真になる。

### 勝ち筋

- 出力が画面の中で終わらず、実物になる。完成品の写真は持ち主が自分から投稿したくなる
- 「写真・図案・完成品」の3枚並びは、説明なしで何のアプリか伝わる画面1枚になる
- 「アイロンビーズ 図案」のように検索する目的がはっきりしている
- 夏休みの自由研究、冬休み、母の日・父の日の贈り物と、毎年決まった時期に需要が来る
- 図案を作る、ビーズを置く、完成品を残す、と1作品ごとに何度も開く用事がある

### 変換の仕様

1. 写真を選ぶか撮る。正方形に切り抜く
2. 大きさを選ぶ。1枚（29×29マス）を基本に、2×2枚（58×58マス）まで並べられる
3. 色数を選ぶ（8・16・24色、または手持ちの色だけ）
4. 変換：写真をマス目の数に縮め、各マスの平均色を人の見え方に近い色空間（CIELAB）で比べて、いちばん近いビーズの色に置き換える。ディザ（色を混ぜて中間色に見せる処理）は初期設定でオフにし、くっきりした絵にする
5. 仕上げ：背景の色を1回押して透明にする、黒いふちどりを付ける、1マスずつ塗り直す、似た色をまとめる
6. 出力：番号付きの図案、色ごとの必要粒数（予備10%込み）、ビーズを並べた見た目の完成予想図

### 主要機能と画面

| 画面・機能 | 内容 |
| --- | --- |
| 図案を作る | 上の1〜6。変換は端末内で数秒 |
| 材料表 | 色ごとの粒数。手持ちの在庫と比べて足りない色を赤で出す |
| 作業ガイド | 1色ずつ置く場所を光らせ、行ごとに済みの印を付ける。途中で閉じても続きから再開する |
| 原寸印刷 | 5mm間隔でA4に印刷し、透明なプレートの下に敷いてなぞれる |
| 作品帳 | 完成品の写真・図案・日付・使った粒数を残す。写真・図案・完成品の3枚並び画像を作る |
| 在庫 | 持っている色と量を登録する。図案を作るとき「手持ちの色だけ」で変換できる |

### 拡散と継続の設計

- シェア画像は「元の写真・図案・完成品」の3枚並び。完成品の写真がないときは完成予想図で代わりにする
- 作品帳の完成数と使った粒の総数を記録として見せる（「これまでに12,480粒」）
- 季節のお題（夏休みの自由研究の手順書、母の日の似顔絵）をアプリ内に出す
- 自由研究向けに「写真から図案ができるまで」を説明する手順書をPDFで書き出せるようにする

### 収益化

子どもも使うので広告は入れない。Google Play のファミリー向けポリシーと広告SDKの年齢対応を避ける意味もある。無料で1枚（29×29マス）・16色・図案3件の保存まで使える。「ビズマ Pro」¥730 買い切りで次を解放する。

- 2×2枚までの大きな図案、全色、手持ちの色だけで変換
- 作業ガイド、原寸印刷、作品帳と図案の保存の無制限
- シェア画像の透かしなし

### データと技術

- 変換は Dart の image パッケージを別スレッド（isolate）で動かし、画面を止めない。写真は端末の外に出さない
- 色の一覧はアプリに同梱する。実物のビーズを同じ照明で撮って色の値を決め、画面の色との差を測っておく
- 図案と作品帳は端末内のSQLiteと画像ファイル。原寸印刷は pdf パッケージで作る
- 背景の自動切り抜きは初版では入れず、1回押して背景色を消す方式にする。自動化は次の版で iOS の Vision と Android の ML Kit を検討する

### リスクと対策

| リスク | 対策 |
| --- | --- |
| 画面の色と実物のビーズの色がずれる | 実物を撮影して色を決め、材料表に「画面と実物は色味が違う」と明記する |
| メーカー名や色番号を出すと商標の問題になりうる | 初版は「赤・こい赤」など一般名の汎用色にする。メーカー別の色番号を出すかは別途決める |
| 利用者がキャラクターの画像を変換して投稿する | アプリにはキャラクターの見本を一切入れない。利用規約とシェア画面に「自分で撮った写真を使ってください」と書く |
| 海外の図案アプリと比べられる | 日本語の作業ガイド、原寸印刷、作品帳、自由研究の手順書で差を付ける |
| 子どもの写真を扱う | 写真は端末内だけで処理し、通信しない。プライバシーポリシーに明記する |

### 開発工程（約3〜4週）

1. 1週目：変換の仕組み、色の一覧の作成（実物の撮影を含む）、図案と材料表の表示
2. 2週目：仕上げの編集、作業ガイド、完成予想図
3. 3週目：作品帳、在庫、原寸印刷、シェア画像
4. 4週目：買い切り、実機確認（印刷した図案が5mm間隔で正しく出るか）、ストア素材
