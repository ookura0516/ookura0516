# ヨンクミ 設計書

16語を4組に分けるだけの、日替わりの言葉パズルです。仕分けの軸は読み・漢字・季語など、日本語ならではのひねりにしています。サーバーもアカウントも使わず、問題はアプリに同梱します。

- 元の企画：「人気ジャンル分析から作るアプリ4案 設計書（第2弾）」の案3と「共通の技術方針」（ブランチ `claude/dazzling-planck-qofymj` の `アプリ4案_設計書_第2弾.md`）
- 設計書と食い違う判断は [README](../README.md#設計書と変えたところ) にまとめた

## 1. ルール

- 4×4のタイルに16語。同じ仲間の4語を選んで「決定」
- 正解すると、その4語が帯になって上に並び、軸の名前（例：「「はし」と読む」）が出る
- 4組すべて当てればクリア。間違えは4回まで。4回目で終わり、残りの組を答えとして見せる
- 3語が同じ組のときだけ「あと1つ！」と出す
- 前に決定したのと同じ4語でもう一度決定しても、間違いに数えない（「その4語はもう試しました」）
- 帯の色は難易度。明るい色から暗い色へ **柿（やさしい）→ 紅 → 栗 → 墨（とてもむずかしい）**。NYTの4色（黄・緑・青・紫）は使わない。色が見分けにくい人のために、明るさの順と、設定の「色名を表示する」（帯と結果に「柿・紅・栗・墨」を文字でも出す）で区別できるようにした

## 2. 画面

起動するとその日の問題がすぐに出る（タイトル画面は置かない）。初回だけ、先にチュートリアル問を出す。

| 画面 | ファイル | 内容 |
| --- | --- | --- |
| 今日の問題 | `lib/ui/screens/puzzle_screen.dart` | 4×4タイル、残りの間違え回数（●4つ）、「あと1つ！」などの一言、シャッフル・選択解除・決定。上にアーカイブと設定 |
| 結果 | `lib/ui/screens/result_screen.dart` | 4色グリッド（決定の順に1行4マス）、決定の回数、連続日数、画像（縦長・正方形）と文字の共有、全組の軸と解説、ひっかけの説明。下だけにバナー広告と「広告を消す」 |
| アーカイブ | `lib/ui/screens/archive_screen.dart` | 過去の日の一覧。解いた日は結果グリッドのサムネイル。無料は直近7日分（今日と、7日前まで）。それより前をタップすると購入の案内 |
| 設定 | `lib/ui/screens/settings_screen.dart` | 遊び方、遊び方の問題をもう一度、成績、色名の表示、通知（1日1回・初期オフ・時刻）、全問パック |
| 遊び方 | `lib/ui/screens/how_to_screen.dart` | ルール、帯の色、軸の種類、連続日数の数え方 |
| チュートリアル | `lib/core/tutorial.dart` | 軸がやさしい固定の1問（果物・「山」の字・冬の季語・「かみ」と読む）。「とばす」もできる。成績と連続日数には数えない |

## 3. 日替わり

- 第1日は `lib/core/schedule.dart` の `kFirstDay`（いまは 2026-11-01。リリース日に合わせて変える）
- 日本時間の0時で次の番号に進む。端末のタイムゾーンには関係なく、全員が同じ日に同じ番号（`ookura_daily` の `DailyClock`）
- アプリを開いたまま0時を過ぎても、タイマーとアプリ復帰時の確認で今日の問題に切り替わる
- 収録した問題があるうちは第N日に第N問。尽きたら、それまでの問題から日付で決まる1問を「再出題」として出す。全員が同じ日に同じ問題になり、前の日と同じ問題は続かない（`PuzzleSchedule`）

## 4. 問題データ

### 形式（`tool/puzzles/puzzles.json`、1問1オブジェクト）

| フィールド | 内容 |
| --- | --- |
| `number` | 通し番号。第1日＋番号で日付が決まる |
| `groups[4]` | `title`（軸の名前）、`axis`（軸の種類と値）、`words[4]`、`difficulty`（1〜4）、`note`（解説1行） |
| `readings` | 16語すべての読み（ひらがな）。同じ読み・隠れた県名・回文の判定に使う |
| `decoys` | ミスリード：`word`、`title`（何に見えるか）、`axis`（当てはまる軸）。結果画面の「ひっかけ」と、検証の「ちょうど4語」の数え方に使う |
| `tags` | 軸の種類（書き出し時に `axis.type` から作る。成績の軸別分析用） |

### 軸の種類（`lib/core/axis.dart`）

| 種類 | value | 当てはまる語 | 例 |
| --- | --- | --- | --- |
| 同じ読み `reading` | はし | 読みが同じ | 橋・箸・端・嘴 |
| 同じ漢字 `kanji` | 金 | 表記に含む | 金曜・貯金・針金・金庫 |
| 季語の季節 `season` | 冬 | 辞書の季語でその季節 | 水仙・山茶花・焚き火・湯豆腐 |
| 隠れた県名 `hidden` | 県名 | 読みに都道府県名を含む（ひらがなで出題） | みえっぱり・しがらみ・ふくいん・こうちょう |
| ことわざの穴 `proverb` | 集まりの名前 | 同じ形のことわざの穴に入る | 小判・真珠・金棒・釘（猫に小判…） |
| 数え方 `counter` | 棹 | 辞書の数え方 | 箪笥・羊羹・三味線・長持 |
| カタカナ語の元 `origin` | ドイツ語 | 辞書の元の言語 | アルバイト・カルテ・ワクチン・エネルギー |
| 「お」が付く `oPrefix` | — | 前に「お」で別の言葉 | 化け・守り・洒落・節介 |
| 回文 `palindrome` | — | 読みが3文字以上の回文 | 新聞紙・トマト・八百屋・子猫 |
| へんな軸 `list` | リスト名 | 辞書のリストにある | 山手線の駅、七福神、干支、将棋の駒、寿司ネタ、惑星、月の古い呼び名、春と秋の七草、トランプのマーク |
| そのほか `manual` | 自由 | 自動では確かめない（チュートリアルの「果物」だけ） | — |

### ミスリード

1語が2つの軸に当てはまるように組む（「金魚」は「金」を含むが夏の季語の組）。検証で「分け方が1通りしかない」ことを確かめるので、ミスリードがあっても答えは1つに決まる。収録60問はすべて1つ以上のミスリードを持つ（計90個）。

### 簡易暗号（`lib/core/puzzle_cipher.dart`）

- 1問ずつ、その問題の日付（例 `2026-11-04`）から作った鍵で XOR し、base64 にする。頭に印（`YK1:`）を入れて、鍵が違えば開けないと分かるようにする
- アプリは今日以前の問題しか開かない（`PuzzleBundle.open`）。アセットを開いても先の問題がそのままは読めない
- 鍵の作り方はアプリに入っているので、本気で解析されれば読める。「うっかり見える」を防ぐためのもの

## 5. 作問 CLI（`tool/yonkumi.dart`）

yonkumi/ で `dart run tool/yonkumi.dart <コマンド>`。

| コマンド | すること |
| --- | --- |
| `validate` | 収録した問題をすべて検証する |
| `check <file.json>` | 下書きの1問を、それより前の問題と合わせて検証する |
| `build` | 検証して、エラーがなければ `assets/puzzles.json` を書き出す |
| `candidates <種類>` | 辞書から軸の候補（当てはまる語が4つ以上ある軸）を出す。使った回数も出す |
| `axes <語>...` | 語が当てはまる軸をすべて出す（ミスリードを組むとき用） |
| `summary` | 軸の種類ごとの組数と平均の難易度 |

### 自動検証（`lib/core/validator.dart`）

- 16語に重複がない。各組4語。難易度は1〜4が1組ずつ
- 各語は7文字以下。16語すべてにひらがなの読みがある（辞書の読みと違えば注意）
- 各組の軸に当てはまる語が、ミスリードとして書いた語を除いて**ちょうど4つ**（16語すべてを辞書で引いて確かめる）
- ミスリードに書いた語が、本当にその軸に当てはまる
- 16語を4組に分ける分け方が**1通りだけ**
- 過去問と同じ4語の組がない。同じ軸で3語以上重ならない（8語以上かぶれば注意）

### 辞書（`tool/dict/`、アプリには入れない）

| ファイル | 中身 |
| --- | --- |
| `readings.json` | 語と読み（同じ読み・同じ漢字・隠れた県名・回文の候補出し） |
| `kigo.json` | 季語と季節（約270語） |
| `counters.json` | 数え方と語 |
| `origins.json` | カタカナ語と元の言語。元が英語のものも入れておき、取り違えを見つける |
| `o_words.json` | 前に「お」で別の言葉になる語。丁寧の「お」（お茶・お金）は入れない |
| `proverbs.json` | ことわざの集まり（「AにB」「AよりB」「名人も失敗する」「ごくわずか」「三のことわざ」）と穴の語 |
| `hidden.json` | 隠し語のリスト（都道府県名の読み47） |
| `lists.json` | へんな軸のリスト |

検証は辞書に書いてあることしか分からない。問題に出す語は、どの軸に当てはまるかを辞書に足してから検証する（足していないと、ミスリードや別解を見落とす）。

### 作問の流れ

1. `candidates` で軸を選ぶ（例：`candidates reading` で同音の語の組）
2. `axes` で、ほかの軸にも当てはまる語を探してミスリードを組む
3. 下書きを JSON に書き、`check` で検証する
4. `tool/puzzles/puzzles.json` の末尾に足し、`build` でアセットを作り直す

## 6. 記録と成績

- 端末の shared_preferences に JSON で残す（`lib/game/play_log.dart`）。サーバーには送らない
  - 記録（1日1件）：第何日、出した問題の番号、解き終えた日、決定した4語の並び、クリアしたか、間違いの回数
  - 解きかけ：決定した4語の並び。開き直すと続きから
- 結果グリッドと成績は記録から毎回作り直す（画像は残さない）
- 成績：遊んだ問題数、クリア数と率、パーフェクト（間違いなし）、平均の間違い、連続日数（今と最長）。軸ごとの正解率は全問パック
- 連続日数：**その日の問題をその日のうちに解き終えた日**を数える。間違い4回で終わっても途切れない。アーカイブで後から解いた日は数えない。今日まだでも、昨日まで続いていれば途切れていない扱い

## 7. 共有

- 文字：`ヨンクミ 第12問（11/12）`、絵文字の四角（🟧🟥🟫⬛）、`間違い 1/4・連続3日`、`#ヨンクミ`。答えは入れない
- 画像：1080×1350（縦長）と1080×1080（正方形）。画面に出さずに組んでPNGにする（`ookura_daily` の `renderShareImage`）。アプリ名とハッシュタグを小さく入れ、ストアのリンクは入れない
- どちらも share_plus で OS の共有シートへ

## 8. ウィジェット

- 小（ホーム）とロック画面（iOS）：「第N問」「未解決／解決済み」「連続N日」。語はネタバレになるので出さない。タップでアプリを開く
- アプリは home_widget で今日と翌日の2日分と切り替え時刻を書く（`lib/game/widget_data.dart` → `ookura_daily` の `DailyWidgetSnapshot`）。翌日分は「未解決」で、今日を解いていなければ連続は0
- iOS はタイムラインに切り替え時刻の項目を置き、Android は切り替え時刻に更新を予約する。アプリを開かなくても0時に進む
- ネイティブ側：`android/app/src/main/kotlin/com/ookura/yonkumi/YonkumiWidgetProvider.kt`、`ios/YonkumiWidget/YonkumiWidget.swift`

## 9. 通知

- 1日1回・初期オフ。文面は「第N問が出ました」だけ。時刻は6〜22時から選ぶ（初期8時）
- 番号が日ごとに変わるので、繰り返し通知ではなく7日分を1件ずつ予約し、アプリを開くたびに予約し直す。今日をもう解いた日は今日の分を出さない（`lib/game/daily_notice.dart`）
- flutter_local_notifications で端末の中だけで予約する。正確なアラームの権限は求めない（数分ずれてよい）

## 10. 広告と購入

| 区分 | 内容 |
| --- | --- |
| 無料 | 今日の問題、直近7日のアーカイブ、結果の共有、ウィジェット、成績。広告は結果画面の下のバナー1枚だけ |
| 全問パック（買い切り ¥600） | 広告削除、全アーカイブ、成績の軸別分析 |

- 全画面広告（インタースティシャル）とリワード広告は使わない。問題の画面には広告を出さない
- 購入の入口は、アーカイブの8日より前をタップしたときと、バナーの「広告を消す」、設定
- 広告は `AdMobService`（アンカー アダプティブ バナー、非パーソナライズ、年齢区分 G、EEA などでは UMP の同意フォーム）。広告ユニット ID は `lib/monetize/ad_unit_ids.dart`。本番 ID を入れて `isPlaceholder` を false にするまで、リリースビルドでは広告を出さない（デバッグはテスト広告）
- 購入は `StorePurchaseService`（in_app_purchase、非消耗型 `yonkumi_fullpack`）。購入済みは端末に保存し、通信がなくても分かる。Android は起動時に復元、iOS は「購入を復元」で復元する。サーバーでの検証はしない（ひそかぎと同じ判断）
- テストと画面の確認には、ネットワークを使わない `PlaceholderAdService`・`PlaceholderPurchaseService` を使う
- 設定に、プライバシーポリシーへのリンクと、同意が要る地域だけ「広告のプライバシー設定」を出す

## 11. 共通部品（`packages/ookura_daily`）

キップテンとタンザクでも使う前提で、アプリ固有の言葉を持たない。

| 部品 | 内容 |
| --- | --- |
| `CivilDate`, `DailyClock` | 時差を持たない日付。決まった時差（既定 +9時間）の0時で替わる通し番号、次の切り替え時刻 |
| `computeStreak` | 遊んだ日の番号の集まりから、今の連続と最長 |
| `DailyWidgetEntry`, `DailyWidgetSnapshot` | ウィジェットに書く今日と翌日の2日分（すべて文字列） |
| `DailyWidgetSink`, `HomeWidgetSink` | home_widget への書き出しと、切り替え時刻の更新予約 |
| `renderShareImage`, `ShareImageFormat` | ウィジェットを画面に出さずにPNGへ（1080×1350、1080×1080） |
| `ShareSheet`, `SystemShareSheet` | share_plus の共有シート |
| `emojiGrid` | 色の番号の並びを絵文字の行に |
