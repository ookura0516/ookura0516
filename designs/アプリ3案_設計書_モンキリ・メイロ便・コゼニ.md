## 概要と比較

3案とも「リンクを開いた人が、その場で遊べる」ことを広がり方の中心に置く。リンクの中身（作品・手紙・問題）はURLに入れ、サーバーには何も保存しない。

| 項目 | モンキリ | メイロ便 | コゼニ |
| --- | --- | --- | --- |
| 一文 | 折って、切って、ひらく切り紙 | 解いた人だけが読める、迷路の手紙 | 財布の小銭がいちばん減る払い方を当てる |
| 種類 | 作る（作品） | 送る（手紙） | 解く（日替わりと勝負） |

## Web体験サイトの共通設計

### サイトの構成

1アプリにつき Cloudflare Pages のプロジェクトを1つ作る。アプリを開くリンク（Universal Links・App Links）の設定ファイルがドメインごとに要るため、3案を1つのサイトにまとめない。

```
https://<アプリ名>.pages.dev/
├─ /                静的なLP（HTMLとCSS。JavaScriptは最小限）
├─ /play/           体験版（Flutter Web。アプリと同じ Dart のコード）
├─ /open/           共有リンクの入口（中身は /play/ と同じ。OGPだけ違う）
├─ /privacy.html    プライバシーポリシー
├─ /support.html    サポート
├─ /.well-known/    apple-app-site-association、assetlinks.json
├─ /_headers        ヘッダーの設定（Cloudflare が読む。配信はされない）
└─ /_redirects      転送の設定（同上）
```

- `_headers`：拡張子のない `/.well-known/apple-app-site-association` に `Content-Type: application/json` を付ける。体験版のファイル（`/play/assets/*` など）は長くキャッシュし、`index.html` は短くする
- `_redirects`：`/play/*` と `/open/*` を、それぞれの `index.html` に返す（200）。体験版の画面ごとにURLのパスを変えて計測するため（「計測」）
- `.well-known/` のような点で始まるフォルダが `wrangler pages deploy` で上がり、正しい型で配信されるかは、公開前に確かめる

プロジェクト名の候補は `kozeni`、`monkiri`、`meirobin`。`pages.dev` のサブドメインはプロジェクト名から決まり、空きは未確認。Cloudflare は使い始めの48時間、新しく作れるプロジェクトの数を絞っている（Pages の上限のページ）ので、3つを一度に作れないことがある。

LPの中身（3案共通の並び）

1. 一文と「いますぐ遊ぶ」ボタン、ストアのバッジ
2. 動いている様子（短い動画かGIF）を1つ。宣伝動画のイメージ版（縦20秒・横30秒、3案ぶん）は [promo/](promo/README.md) にある。アプリができたら実機の録画で作り直す
3. 遊び方を3ステップで
4. アプリ版でできること（Webとの違いの表）
5. よくある質問、プライバシーポリシーとサポートへのリンク

LPは静的なHTMLなので、検索に載り、リンクを貼ったときの表示（OGP）も確実に出る。ストアに登録する「マーケティングURL」「サポートURL」「プライバシーポリシーURL」もこのサイトでまかなえる。

### アプリとWebでコードを分ける場所

Flutter のプロジェクトは1つ。入口を2つにする。

| 場所 | 中身 | アプリ | Web |
| --- | --- | --- | --- |
| `lib/main.dart` | アプリの入口 | ○ | ― |
| `lib/main_web.dart` | 体験版の入口 | ― | ○ |
| `lib/core/` | 純粋な Dart（ルール、生成、採点、リンクの符号化） | ○ | ○ |
| `lib/render/` | CustomPainter の描画 | ○ | ○ |
| `lib/ui/` | 画面 | ○ | ○（体験版で使う画面だけ） |
| `lib/data/` | drift（SQLite）の保存 | ○ | ― |
| `lib/platform/` | 共有、リンクの受け取り、通知 | ○ | Web用の実装に差し替え |
| `lib/monetize/` | 購入 | ○ | ― |
| `site/` | LP、プライバシーポリシー、OGP画像、`.well-known/` | ― | ○ |
| `tool/` | サイトの組み立て、フォントの絞り込み、作問 | ― | ― |

- 体験版は `flutter build web -t lib/main_web.dart --base-href /play/` で作る。`main_web.dart` からは `lib/data/` と `lib/monetize/` を参照しない。`dart:io` や `dart:ffi` を使うコードが Web のビルドに入ると失敗するため
- 体験版はデータベースを持たない。覚えておくのは「今日遊んだか」と直前の結果だけで、`shared_preferences`（ブラウザでは localStorage）に入れる。作品帳・文箱・成績はアプリだけの機能にする。これがアプリを入れる理由にもなる
- push のたびに GitHub Actions で `flutter test` と `flutter build web` を回し、Web に入れてはいけないコードが混ざったらそこで気づけるようにする（`keshiin.yml` と同じ考え方）

### 同じ結果を出すための決まり

リンクをアプリで作り、ブラウザで開く。両方で同じ中身にならないと困る。

- Dart の整数は、アプリ（64ビット）とブラウザの JavaScript 版（53ビットまで正確）で桁あふれの結果が違う。乱数やハッシュは、32ビットに切りそろえた xorshift の形で書き、掛け算で大きな数を作らない
- 決まった入力に対する期待値をテストに書き、`flutter test` と `flutter test --platform chrome` の両方で通す
- 生成の手順（迷路の作り方、問題の作り方）に結果を頼らない。リンクには生成した結果そのもの（壁の並び、問題の金額と財布）を入れる。生成の手順をあとで直しても、古いリンクが開けなくならない
- 小数の計算（三角関数など）は端末で末尾がずれることがある。採点には整数だけを使う

### 共有リンク

```
https://<アプリ名>.pages.dev/open/#v1.<base64url のデータ>
```

- データは `#` のうしろに入れる。`#` 以降はサーバーに送られないので、作品も手紙もサーバーのログに残らない
- 先頭に版数、末尾に検査用の1バイト（CRC-8）を付ける。途中で切れたリンクは「リンクがとちゅうで切れています」と出す
- 長さの目安は、コゼニ約70文字、メイロ便約120〜370文字、モンキリは普通の作品で約270文字・上限で約800文字（検算済み）。X・LINE・メールで切れないかは公開前に実測する
- アプリが入っている端末では、同じURLでアプリが開く（iOS の Universal Links、Android の App Links）。受け取りには `app_links` パッケージを使う。`#` 以降がアプリに渡るかは実機で確かめる
- X や LINE のアプリ内ブラウザからはアプリが開かないことが多い。体験版の中に「アプリで開く」ボタンを置く

### 読み込みの速さ

Flutter Web は最初に数MBを読み込む。次の順で軽くする。

- LPは静的なので先に表示される。LPを表示したあとで体験版のファイルを先読みしておく
- `/play/` と `/open/` は、Flutter の準備ができるまでHTMLとCSSだけの絵（たたんだ紙、封筒、レジ）を出す
- 日本語フォントが一番重い。体験版には、画面の決まった文言とかな・数字だけに絞ったフォント（Noto Sans JP、OFL）を同梱する。絞り込みは `tool/` のスクリプトで行い、文言を変えたら作り直す。アプリ（iOS・Android）は端末のフォントを使う
- メイロ便で入力できる文字をかなと数字に限るのは、この制約とも合わせている
- 目標は、4G回線で `/play/` を開いてから5秒以内に触れること、転送量3MB以下。実測して超えたら、フォントと画像を削る
- `flutter build web --wasm` を使うか、JavaScript 版だけにするかは、Flutter 3.47 で実測して決める

### Webからアプリへの導線

- 体験が一区切りついたとき（結果、ひらいたあと、読んだあと）に1回だけ、「アプリ版でできること」とストアのバッジを出す。遊んでいる途中には出さない
- iOS の Safari には Smart App Banner を出す（`apple-itunes-app` のメタタグ）
- パソコンで開いた人には、スマホで開くためのQRを出す
- ストアへのリンクに計測用の印を付ける（App Store はキャンペーンリンク、Google Play は `referrer`）。Web経由のインストール数を各ストアの管理画面で見る

### OGP（リンクを貼ったときの画像）

- 初版は入口ごとに決まった画像を1枚ずつ用意する（LP用、今日の問題用、届いたリンク用）。`/open/` の画像は「紙がとどきました。ひらいてみて」のように、開く動機になる一言にする
- 結果や作品に合わせた画像を出すには、データを `#` ではなく `?` で送り、Pages Functions（Cloudflare Workers）で画像を作る必要がある。無料プランでは Workers の上限（1日10万リクエスト）に数えられる。`_headers` の設定は関数が返す応答には効かないので、ヘッダーは関数の中で付ける。モンキリの作品とコゼニの結果では公開後に検討する。メイロ便は手紙の中身をサーバーに送らないので、決まった画像のままにする

### 計測

- Cloudflare Web Analytics（無料、Cookieを使わない）で、ページごとの表示回数を見る。1アカウント10サイトが目安の上限（FAQ）。3案と別のセッションの4案（PR #10）を合わせて7サイト
- 追いたい数字は、LPから体験を始めた割合、最後まで遊んだ割合、共有した割合、ストアのボタンを押した割合、Web経由のインストール数
- Cloudflare Web Analytics には、ボタンを押した回数などのカスタムイベントがまだない（FAQ）。代わりに、体験版の区切りごとにURLのパスを変える（`/play/start`、`/play/done`、`/play/shared`）。1ページで動くアプリでも、パスが変わるたびに表示として数えられる。Flutter 側は `usePathUrlStrategy()` を使い、共有リンクのデータは `Uri.base.fragment` から自分で読む
- クエリ文字列は記録されない（FAQ）。`?utm_` で流入元を分けることはできないので、流入元はリファラーで見る
- ストアのボタンを押した割合は、Web 側では数えない。各ストアの管理画面で、計測用の印を付けたリンク経由のページ表示とインストールを見る
- 広告ブロッカーで計測のスクリプトが止まることがある（FAQ）。数字は実際より少なめに出る
- プライバシーポリシーに「サイトの表示回数を、個人を特定しない形で数える」と書く

### デプロイと同時公開の段取り

- GitHub Actions で体験版をビルドし、LPと合わせた静的ファイルを `wrangler pages deploy` で直接アップロードする（Cloudflare の Direct Upload）。Flutter のビルドは GitHub Actions で行い、Cloudflare 側のビルド機能は使わない
- シークレットは `CLOUDFLARE_API_TOKEN`（権限は Account → Cloudflare Pages → Edit）と `CLOUDFLARE_ACCOUNT_ID` の2つ。このセッションには Cloudflare の連携がないので、デプロイは GitHub Actions からだけになる
- ストアの審査では、プライバシーポリシーとサポートのURLが開ける必要がある。審査に出す前に、LP（ストアのボタンは「近日公開」）とプライバシーポリシー、サポートだけを本番に出す。体験版は本番以外のブランチとしてデプロイし、プレビューのURLで確認しておく
- App Store は「手動でリリース」、Google Play は公開タイミングを自分で決める設定で審査に出す
- 両方の承認が出た日に、ストアで公開 → LPのボタンをストアへのリンクに切り替え → 体験版を本番に出す → 告知、の順で行う
- 告知は画像か動画を先に投稿し、リンクは返信に付ける（第2弾の設計書の方針と同じ）

### 費用

- Cloudflare Pages の無料プランで始める。月額はかからない。案内ページに「All plans come with unlimited sites, seats, requests, and bandwidth」とあり、転送量の上限を気にしなくてよい
- 無料プランの上限（Pages の上限のページ）：1サイト2万ファイル、1ファイル25MiB、1アカウント100プロジェクト。Flutter Web の出力はこの範囲に収まる見込み。Cloudflare 側でビルドしないので、月500回のビルドの上限には当たらない
- 上限のページに、非商用に限る旨の記載は見当たらなかった。ただし利用規約そのものはまだ読んでいないので、人が確かめる（「人がやること」）
- 転送量は、1回の体験で約3MBとして、月1万回で約30GB
- Vercel をやめた理由：Vercel の Fair Use Guidelines に「Hobby teams are restricted to non-commercial personal use only」とあり、商用の例に「Advertising the sale of a product or service」（商品やサービスの販売の宣伝）が挙がっている。有料の機能があるアプリの宣伝サイトはこれに当たる。Vercel を使うなら Pro（開発者1人 $20／月）が要る（2026年11月22日に確認）

## 共通の技術方針（アプリ側）

- Flutter 3.47（Dart 3.13）。構成とパッケージの選び方は `hisokagi/` と `keshiin/` に合わせる（provider、shared_preferences、drift、in_app_purchase、flutter_lints）
- バックエンドなし、アカウントなし。Cloudflare Pages に置くのは静的ファイルだけ
- 3案とも広告なしの買い切り。子どもが使う場面があること、Web体験版に広告を置かないことと合わせる。同意画面（ATT・UMP）の作業も要らなくなる
- 共有画像は `PictureRecorder` で 1080×1350 に直接描く（ケシインで決めたやり方）。画像の右下に小さくアプリ名を入れ、ストアのリンクは入れない
- 評価依頼は、作品の保存、手紙を送ったあと、5問の結果の直後。365日に3回まで
- 日付で切り替わるものは日本時間の0時
- `ookura_core` などの非公開パッケージは、この環境では使えない（ひそかぎ・ケシインと同じ）
- ウィジェットは3案とも初版に入れない。Webで体験できない機能より、リンクまわりを先に仕上げる。次の版でケシインのウィジェットのコードを流用する

## 案1 モンキリ（折って、切って、ひらく）

紙を折り、指で切り、ひらくと模様になる。紋切り（江戸時代からある、折った紙を切って紋の形を作る遊び）をスマホに移す。

### 概要と勝ち筋

一文：折って、切って、ひらく。開くまでわからない切り紙。

対象は3つ。

- 子どもと工作をする親、保育士、先生。季節の飾りを作る
- 和柄・家紋・切り紙が好きな大人
- 作った模様をSNSに載せる人

勝ち筋

- リンクを開くと、たたんだ紙が出る。「ひらく」を押すまで模様が見えない。受け取った人がその場で体験でき、自分でも切りたくなる
- 雪の結晶だけでなく、桜・梅・麻の葉・亀甲などの紋を、型紙でなぞって覚えられる
- 画面で作った模様を、実物の紙で切るための型紙として印刷できる

### 折り方

重なる枚数を 2n とすると、たたんだ紙は中心角 180°÷n の扇形になる。ひらいた形は、扇形の切り取りを n 回の回転と鏡映で写したもの。

| 呼び名（仮） | 重なる枚数 | 扇の角度 | 代表の模様 | 区分 |
| --- | --- | --- | --- | --- |
| 二つ折り | 2 | 180° | 蝶、ハート | 無料 |
| 四つ折り | 4 | 90° | 菱、四つ葉 | 無料 |
| 八つ折り | 8 | 45° | 四弁・八弁の花 | 無料 |
| 雪折り | 12 | 30° | 雪の結晶、麻の葉、亀甲 | 無料 |
| 三方折り | 6 | 60° | 三つ葉、鱗 | 道具箱（有料） |
| 花折り | 10 | 36° | 桜、梅、星 | 道具箱（有料） |

呼び名は仮。伝統的な紋切りでの呼び方（三つ折り・五つ折り・六つ折り）と合わせるかは、資料を確かめてから決める。

### 切る・ひらく

切る

- 画面には扇形の紙が大きく出る。1本指で切り、2本指で拡大と移動
- 道具は2つ。「なぞる」（指でなぞった線）と「点でつなぐ」（点を順に打って直線で結ぶ。麻の葉のような直線の模様用）
- なぞり終えると、線の終わりと始まりが直線で結ばれ、その内側が切り取られる。紙の外から入って外に出れば、ふちからの切り込みになる。規則はこの1つだけにする
- もどす、やりなおす、全部やりなおす
- 折り目の辺を全部切ると、ひらいたときに紙がばらばらになる。切ることはできるが、「ひらく」の前に知らせる

ひらく

- 実際に紙を開く順に、段ごとに倍々にひらく。雪折りなら 30°→60°→180°→360° の3段
- 1枚めくるごとに、紙の音と振動を付ける。音は自作する
- ひらいたあとは、保存、共有、たたみ直して切り足す、のどれか

### データと技術

切り取りの持ち方

- 切り取り1つは、点の並び（多角形）。なぞった線は点を間引き（Ramer–Douglas–Peucker 法）、扇形を囲む正方形の中の 0〜255 の整数にそろえる
- 保存する作品、リンクの中身、採点に使う形は、すべてこの整数の点から作る。保存した作品とリンクで開いた作品が同じ形になる

リンクの中身（v1）

| 中身 | 大きさ |
| --- | --- |
| 版数と折り方 | 1バイト |
| 紙の形と色 | 1バイト |
| 切り取りの数 | 1バイト（24個まで） |
| 切り取りごとの点の数と座標 | 1＋点の数×2 バイト |
| 検査（CRC-8） | 1バイト |

点の合計は280個まで。超えそうなときは「これ以上は切れません」と出す。切り取り6個・各16点の作品で約270文字、上限で約800文字になる。

描画

- ひらいた形は、紙を描いたあと、切り取りを 2n 通りに写して透明で塗りつぶす（`saveLayer` と `BlendMode.clear`）。図形どうしの演算は使わない
- 一度描いた作品は画像にして持っておき、切り取りが変わったときだけ描き直す。影はその画像から作る
- 切っている間は扇形だけを描き直す。ひらいた形は「ひらく」を押したときに作る
- 書き出しは `PictureRecorder` で、無料は1080px、有料は2048pxと4096px

お題の採点

- 扇形を 128×128 のマスに分け、マスごとに「切り取られたか」を整数の計算だけで判定する。ひらいた形全体で比べるのと結果は同じで、計算は 2n 分の1で済む
- 見本と自分の切り取りを、1マスのずれまで許して比べる。「自分が切ったところのうち見本と合う割合」と「見本のうち自分が切れた割合」の調和平均を点数にする
- 星の境目は70・85・95点から始め、試し遊びで調整する
- 見本を扇形にうすく重ねる手助けを付ける。使ったときは星2つまで

型紙のデータ

- 型紙36種は、アプリのデバッグ用の画面で自分で切って作り、点の並びをJSONにしてアセットに入れる
- 家紋の題材（桜、梅、麻の葉など）は誰でも使えるが、市販の型紙の本の図案は写さない。作った日と元にした資料を記録に残す
- 紋の由来の説明は自分で書く

保存：drift に作品（折り方、紙、切り取り、作った日、お題の番号と点数）と図鑑の進み具合。型紙の印刷は `pdf` と `printing`（A4に、折り方の図と実寸の扇形）。

## 案2 メイロ便（解いた人だけが読める手紙）

メッセージを迷路に隠して送る。正しい道を進むと、文字が順につながって読める。

### 概要と勝ち筋

一文：解いた人だけが読める、迷路の手紙。

対象は3つ。

- 友だち・家族・恋人に短いメッセージを送る人（誕生日、お礼、待ち合わせ）
- 子どもに紙の迷路を作る親や先生
- フォロワーに「解けたら読める告知」を出す配信者や創作者

勝ち筋

- 送ったリンクが、そのままブラウザで解ける迷路になる。受け取る人はアプリを入れなくてよい
- 文字を読みながら解ける。「おたんじょ…」まで来れば、次の文字を予想して道を選べる。ふつうの迷路にない手がかりになる
- 印刷すれば紙の迷路になる。お弁当のメモや宝探しに使える

### 遊びの流れ

送る人

1. メッセージ（かなと数字）、差出人、むずかしさ、便箋の柄を選ぶ
2. 迷路ができる。送る前に自分で解いて確かめられる
3. リンク、QR、画像、PDFのどれかで送る

受け取る人

1. リンクを開くと封筒がひらき、迷路が出る
2. 入口から指で進む。文字のマスを通ると、画面の上の便箋に文字が並ぶ
3. 行き止まりの道には「にせ文字」がある。通ると便箋に入り、戻ると消える。便箋に出るのは、入口から今いる場所までの道にある文字
4. 出口に着くと手紙が読める。差出人、かかった時間、「返事を書く」が出る

操作：進みたい向きにスワイプすると、次の分かれ道か文字のマスまで進む。パソコンでは矢印キー。失敗はない。「正しい道を少し光らせる」ヒントは3回まで。受け取る人に広告や課金は出さない。

### 迷路の作り方

- マス目の迷路。入口から出口までの道は1本だけにする（輪のない迷路）
- 作り方：入口から、行ける隣のマスへランダムに掘り進め、行き止まりになったら戻る方法（深さ優先）。曲がりくねった長い道ができる。出口は、ふちのマスのうち入口からいちばん遠いところ
- 文字の置き方：正しい道の上に、同じ間隔で順に置く。文字の間は2マス以上あける。道の長さが「文字数×3＋6」に足りなければ、作り直すか1段大きくする
- にせ文字：行き止まりの枝に、正しい道と同じくらいの間隔で置く。使う文字は、メッセージの文字を並べ替えたものと、よく使うかな。分かれ道のすぐ隣には置かない

| むずかしさ | 大きさ | 入る文字数 | 正しい道の長さ（400回の試算の中央値） |
| --- | --- | --- | --- |
| やさしい | 9×11 | 12文字まで | 65マス |
| ふつう | 13×17 | 24文字まで | 129マス |
| むずかしい | 17×23 | 40文字まで | 211マス |

入力できる文字：ひらがな、カタカナ、長音、数字、「！？♡☆♪、。」の約190種。漢字と英字は使えない。理由は、小さいマスで読めること、にせ文字を作れること、Web体験版のフォントを軽くできること、URLやIDを書けないようにすること。漢字を打ったときは、その文字に印を付けて「かなで書いてね」と出す。空白と改行は迷路には置かず、手紙を表示するときに元の位置に戻す。

### 主要機能と画面構成

| 画面 | 内容 |
| --- | --- |
| ホーム | 「手紙を書く」、今日の一通、文箱の最近の手紙 |
| 書く | メッセージ、差出人、むずかしさ、形、便箋の柄。入力欄の下に使える文字の説明 |
| ためす | できた迷路を自分で解く。「作り直す」で別の迷路に |
| 送る | リンク、QR、迷路の画像、PDF |
| 解く | 迷路、上に便箋、ヒント、時間 |
| 手紙 | 読めた手紙のカード。「返事を書く」、画像の保存 |
| 文箱 | 送った手紙と解いた手紙の一覧 |
| 設定 | 音、振動、購入、注意書き |

- 今日の一通：日替わりの迷路。中身は季節のことば、ことわざ、なぞなぞの答えなどを自分で書く。初版は90通を入れ、尽きたら最初に戻る。リンクをもらっていない人がLPから来たときに遊べるものにもなる
- 迷路の形（有料）：ハート、星、丸、家。使わないマスを抜いて形にする
- PDF：A4の1ページ目に迷路と便箋の空欄、2ページ目に答え

初版に入れないもの：漢字、絵文字、写真、返事のやりとりを自動でつなぐ機能、ウィジェット。

受け取った人がWebで短い返事を書けるようにしておく。返事もリンクになり、それを開いた人がまた体験する。

### リンクの中身と安全

リンクには、迷路そのものを入れる。

| 中身 | 大きさ |
| --- | --- |
| 版数、大きさ、入口と出口、便箋の柄 | 6バイト |
| 形（四角のときは無し） | 幅×高さ ビット |
| 壁 | 幅×(高さ−1)＋(幅−1)×高さ ビット。ふつうで52バイト |
| 文字 | 1文字につき2バイト（文字表の番号と、正しい道の何マス目か） |
| にせ文字 | 1個につき3バイト（位置と文字） |
| 差出人 | かな8文字まで |
| 検査（CRC-8） | 1バイト |

長さは、やさしい（12文字）で約120文字、ふつう（24文字）で約220文字、むずかしい（40文字）で約370文字。

- 文字はそのままでは読めないように並べ替えて入れる。暗号ではない。URLを調べれば読めるので、秘密を書く用途には向かないと「書く」画面に書く
- メッセージは `#` のうしろに入るので、サーバーには送られない。アクセスの計測にも入れない
- 自由に書いた文が、こちらのサイトの上に表示される。対策は4つ
  - かなと数字だけ、40文字まで。リンクや画像は入れられない
  - 手紙のカードに「この文は、リンクを作った人が書いたものです」と常に出す
  - 禁止語（かな）の判定を、書くときと表示するときの両方で行う。表示する側で引っかかったら「表示できないことばが入っています」と出す
  - サイトの下に連絡先を置く

### 拡散と継続の設計

- 手紙のリンクが広がりの単位。1通送るたびに、受け取った人が体験する
- 「解けたら読める告知」：配信者や創作者が、発売日や当選者を迷路にして投稿する使い方を、LPの使用例に入れる
- 紙：印刷した迷路の写真が投稿される。PDFの下に小さくアプリ名を入れる
- 行事：誕生日、バレンタイン、年賀、卒業、母の日・父の日。行事の2週間前に便箋の柄を足す
- 継続は弱い。送る用事があるときに開く道具と割り切る。毎日の理由は「今日の一通」と連続日数だけにする

### データと技術

- `lib/core/kana_table.dart`：文字と番号の表。入力のゆれ（全角数字、半角カナ）をそろえる処理は、ひそかぎの `kana.dart` と同じ考え方

- `lib/core/maze_gen.dart`：迷路を作る。乱数は自前の32ビットの決定的な乱数

## 案3 コゼニ（小銭がいちばん減る払い方）

レジの金額に対して、財布の小銭がいちばん少なくなる払い方を当てる。日替わりの5問と、友だちへの挑戦状。

### 概要と勝ち筋

一文：財布の小銭が、いちばん減る払い方を当てる。

対象は3つ。

- 現金で払うときに、お釣りを考えて小銭を出す人
- 毎日少しだけ頭の体操をしたい人
- お金の計算を練習する小学生とその親

勝ち筋

- ルールが一目で分かる。金額と財布が出て、硬貨をタップするだけ
- 「460円に1,010円を出して、550円のお釣りをもらう」という身近な工夫が、そのまま正解になる
- 結果がレシートの形になる。同じ5問を友だちに送れる

### 遊び方

1問の流れ

1. 上にレジの金額、下に財布の中身が出る
2. 財布の硬貨やお札をタップして、トレーに出す。トレーの上をタップすると戻る
3. 「はらう」を押す。お釣りは、いちばん少ない枚数で返ってくる
4. 払ったあとの財布の硬貨の枚数で判定する

| 判定 | 条件 |
| --- | --- |
| ◎ | 財布の硬貨が、できる中でいちばん少ない |
| ○ | いちばん少ない枚数より1枚多い |
| △ | それ以外で払えた |
| ミス | 金額が足りない。払い直す |

例（全部の払い方を計算して確かめた）

| 金額 | 財布 | 払い方 | お釣り | 払ったあとの硬貨 |
| --- | --- | --- | --- | --- |
| 460円 | 千円札1、10円1 | 千円札だけ | 500円1、10円4 | 6枚 |
| 460円 | 同じ | 千円札と10円（◎） | 500円1、50円1 | 2枚 |
| 864円 | 千円札1、100円1、50円1、10円2、5円1、1円4（硬貨9枚） | 千円札だけ | 100円1、10円3、5円1、1円1 | 15枚 |
| 864円 | 同じ | 千円札、50円、10円、1円4（◎） | 100円2 | 5枚 |

◎になる払い方が複数ある問題もある（864円の例は8通り）。どれでも◎にする。

店の種類

| 店 | 決まり |
| --- | --- |
| コンビニ | 全部の硬貨とお札が使える。基本の形 |
| 自販機 | 1円と5円が使えない。お札は千円だけ |
| 駄菓子屋 | 金額が小さい。子ども向け |
| お題つき | 「100円玉を3枚にして店を出る」のように、目標が変わる |

バス（お釣りが出ない）やコインランドリー（100円玉だけ）は次の版で足す。

### 主要機能と画面構成

| 画面 | 内容 |
| --- | --- |
| ホーム | 今日の5問、れんしゅう、おけいこ、じっさいの財布、成績 |
| プレイ | レジの金額、トレー、財布（額面ごとに並ぶ）、「はらう」、何問目か、時間 |
| 判定 | お釣りが財布に戻る動き、硬貨の枚数の前後、判定。◎でなければ◎の払い方を見せる |
| 結果 | レシート。画像・文字・挑戦状リンクで共有 |
| 挑戦状 | 相手の名前と結果を見てから、同じ5問を解く。勝ち負けと「やり返す」 |
| 成績 | ◎の割合、平均の時間、連続日数、店ごとの成績 |
| 設定 | 音、振動、通知（初期オフ）、購入、注意書き |

遊び方は5つ。

| 遊び方 | 内容 |
| --- | --- |
| 今日の5問 | 全員同じ5問。コンビニ3問、自販機1問、お題つき1問 |
| 挑戦状 | 遊んだ5問と自分の結果をリンクにして送る。受け取った人は同じ5問で勝負する |
| れんしゅう | 店を選んで、問題が続く |
| おけいこ | 子ども向け。時間を計らない。ぴったり払う→お釣りをもらう→小銭を減らす、の10段 |
| じっさいの財布 | 金額と自分の財布の中身を入れると、◎の払い方を出す |

初版に入れないもの：外国のお金、電子マネーとの組み合わせ、順位表、ウィジェット。

### Web体験版の範囲

| 機能 | Web | アプリ |
| --- | --- | --- |
| 今日の5問 | ○。記録は残らない | ○。連続日数と成績が残る |
| 挑戦状を受ける | ○ | ○ |
| 挑戦状を送る | 今日の5問の結果で送れる | れんしゅうの5問でも送れる |
| れんしゅう | なし | コンビニは無料、ほかの店は有料 |
| おけいこ | 最初の3段 | 3段まで無料、10段まで有料 |
| じっさいの財布 | ○ | ○ |

「じっさいの財布」はWebにも置く。「小銭 減らす 払い方」のような検索から来た人が、その場で使える。

### 拡散と継続の設計

- レシート：結果を、店の名前、日付、5問の金額と判定、合計の時間が並んだレシートの画像にする（1080×1350）。文字だけの共有は「コゼニ 第45回 ◎◎○◎△ 38.2秒」
- 挑戦状：リンクを開くと「◯◯さんから挑戦状。◎4つ、38.2秒」と出て、すぐ同じ5問が始まる。終わると勝ち負けと「やり返す」
- あるある：◎の払い方そのものが話題になる（「864円に1,064円」）。判定の画面に払い方を1行で出し、長押しでコピーできるようにする
- 継続：今日の5問と連続日数。失敗しても連続日数は切れない（遊んだ日で数える）
- 通知は1日1回、初期オフ

### 収益化

無料＋買い切り「がまぐち」¥480、広告なし。

| 区分 | 内容 |
| --- | --- |
| 無料 | 今日の5問、挑戦状、れんしゅう（コンビニ）、おけいこ3段、じっさいの財布、成績 |
| がまぐち ¥480 | れんしゅうの全部の店、おけいこ10段、過去の今日の5問、成績の詳しい表示、レシートの柄 |

### データと技術

払い方の計算

- 額面は 1・5・10・50・100・500円の硬貨と、千円・5千円・1万円のお札。2千円札は入れない
- 財布の出し方を全部試す。額面ごとの枚数の組み合わせは、20枚の財布でも最大2万通りで、すぐ終わる
- お釣りは大きい額面から順に返す。日本の額面では、これでいちばん少ない枚数になる
- 払ったあとの財布（出した分を引き、お釣りを足す）の硬貨の枚数を数え、いちばん少ないものを◎にする
- 店の決まり（使えない額面、目標の違い）は、試す範囲と数え方を変えるだけで同じ計算に乗る

問題のデータ

- 今日の5問は、あらかじめ作ってアセットに入れる（2年分で約25KB）。日付から問題を引くだけなので、アプリとブラウザで必ず同じになる。尽きたら最初に戻る
- 問題を作るCLIを `tool/` に置く。条件は、お札だけで払うと◎にならない、◎とお札だけの差が2枚以上、◎の払い方が多すぎない、の3つ。むずかしさは、◎の払い方で出す枚数と、5・50・500円を作る工夫が要るかで付ける
- れんしゅうの問題は、その場で作る

挑戦状のリンクの中身

| 中身 | 大きさ |
| --- | --- |
| 版数、店の決まりの版 | 2バイト |
| 5問（金額2バイト、財布5バイト） | 35バイト |
| 送った人の判定（5問分）と時間 | 8バイト |
| 名前（かな8文字まで） | 8バイト |
| 検査（CRC-8） | 1バイト |

全部で54バイト、リンクにすると約70文字。問題そのものを入れるので、問題の作り方をあとで変えても古い挑戦状は開ける。

お金の描き方

- 硬貨は、色の付いた丸に額面の数字だけを描く。5円と50円は穴を描く。お札は、角の丸い長方形に額面の数字だけ
- 本物の図柄、肖像、「日本国」「日本銀行券」の文字は描かない
- 通貨に関する法令（通貨及証券模造取締法など）の確認は、まだ人がしていない。公開の前に確認する

コードの置き場所

- `lib/core/money.dart`：額面、財布、お釣り
- `lib/core/solver.dart`：全部の払い方を試して判定する
- `lib/core/shop.dart`：店の決まり
- `lib/core/daily.dart`：日付から今日の5問を引く
- `lib/core/challenge_codec.dart`：挑戦状のリンクとの変換
- `lib/render/`：硬貨、お札、レシート
- drift：遊んだ記録（日付、5問の判定、時間）、れんしゅうの成績、おけいこの進み具合
- テスト：判定（上の例を含む）、店の決まり、リンクの変換、アセットの問題が全部条件を満たすこと
