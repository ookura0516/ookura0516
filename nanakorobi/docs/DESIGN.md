# ナナコロビ（仮） 設計書

目標ごとに「だるま」を1体持ち、開眼で始めて毎日の一歩で模様が入り、達成で両目を入れる目標帳です。挫折しても消えず、起き上がるたびに台座に金の筋が増えます（七転び八起き）。サーバーもアカウントも持たず、外部 SDK は各ストアの IAP だけ。広告なし。

- 企画の元：[人気が出やすいアプリのジャンル別分析（日本市場・2026）](https://claude.ai/artifact/KbRRcX7M2vSZvKtiUdqJFB)の「ヘルスケア・習慣化」に「結果シェア」と「日本文化ネタ」を掛け合わせ、[App Store 検索ギャップ調査](https://claude.ai/artifact/LfdDuiYGRevwXg72dcne6a)で1位だった受験カウントダウンをウィジェットに内蔵する
- 技術方針の共通元：[人気ジャンル分析から作るアプリ3案 設計書](https://claude.ai/artifact/4VthrWYTDkAWNBHg69GdDj)
- この設計書の元（Claude Docs）：[ナナコロビ（仮） 設計書](https://claude.ai/artifact/2ZwPSF3X5zUsBrGcPzcZnx)。節の順と内容はそちらに合わせ、初版の実装で決めたことを 13 章に足した
- 対象：主は受験生とその親（中学・高校・大学・資格）。副は年始に抱負を立てる 20〜40 代
- 使い方の想定：1日1回、10秒。開く → 今日の一歩をタップ → だるまに1筆。それ以外はウィジェットで見るだけ

## 1. 概要と狙い

一文で言うと：だるまに目を入れて、目標を始める。

目標（合格、−3kg、毎日英語、禁酒90日など）を1つ決めると、だるまが1体できる。指で片目を描き入れて「開眼」する。毎日、決めた一歩を1タップで記録すると、だるまに1筆ずつ模様が入る。1日抜けるとだるまは転ぶが、次の記録で起き上がり、台座に金の筋が1本増える。達成したらもう片方の目を入れて両目になり、棚に並ぶ。試験日のような期限がある目標は、ウィジェットに残り日数が出る。

- ジャンルは「ヘルスケア・習慣化」（人気10／実現7）。継続率は最上位だが話題になりにくいので、「結果シェア・診断」型（自分が入る、比較軸、引用で一言添えたくなる余白）と「日本語・日本文化ネタ」で話題性を足す
- 参照事例：Streaks（買い切り¥1,000）、Duolingo のストリーク（D7 +14%）とウィジェット（設置者の半数が6か月以上継続）、Oshibana（ウィジェット主体で100万DL）
- だるまの目入れは、願いを込めて片目を入れ、叶ったらもう片方を入れる風習として全国で知られている。「ルールや価値が一目で分かる」を説明なしで満たす
- 受験カウントダウンの首位アプリには「ウィジェットが0時に進まない」「試験を1つしか載せられない」という直せる不満がある。本案は受験生向けの「合格だるま」に試験日カウントダウンを内蔵して同じ検索語を取りに行く。ただしカウントダウンだけの製品にはしない

他の案と被らない理由：

| 比べる相手 | 向こうの形 | 本案の形 |
| --- | --- | --- |
| ソライロ帳・ケシイン・タンザク | 毎日1つ撮る／詠む→月のグリッド作品 | 目標1つ＝だるま1体。画面はカレンダーではなくキャラクター |
| シリトリンク・ヨンクミ・キップテン | 日替わりの言葉・数のパズル | パズル要素なし |
| ダレウソ・ひそかぎ・灯台守の手紙 | 謎解き | 謎解き要素なし |
| メクマデ（配信中の日めくりカウントダウン） | 日付までの残り日数が主役 | 目標の儀式と毎日の記録が主役で、残り日数は従。画面・文言・ストア説明を別物にして 4.3（類似）を避ける |
| アッチホイ設計書（案内役がだるま） | カメラ判定の昔あそび。だるまは脇役 | だるまが主役の目標帳。絵柄は共有しない |

いま出す理由：受験の需要は9〜1月に集中し、そのあとに正月のだるま市と新年の抱負が続く。12月中旬までに iOS 版を出せば、年末年始の「今年のだるま」投稿と1月の受験本番の両方に乗れる。

## 2. コア体験

作る → 開眼 → 毎日の一歩が本線。記録のない日は転ぶが模様は減らず、次の記録で起き上がって台座の金の筋が1本増える。達成したらもう片方の目を入れて両目になり、期限切れややめるときは片目のまま納める。どちらも棚に残り、同じ目標でひと回り大きいだるまをまた開眼できる。休み券を前日に宣言した日は転ばない。

```
作る ─→ 開眼（片目） ─→ 毎日の一歩（1筆ずつ）─┬─→ 両目（満願）──→ 棚「満願」
                          ↑        │              └─→ 納める ──────→ 棚「納め」──→ ひと回り大きいだるま
                          │        ↓                                                  （同じ目標でまた開眼）
                     起き上がり   転ぶ（記録のない日。模様は減らない）
                    （金の筋 +1）
```

## 3. だるまの育ち方と七転び八起き

1体＝1目標。作るときに決めるのは4つだけ。目標名（腹に入る文字、2〜6字。「合格」「必勝」「走る」「英語」）、色、期限（任意）、毎日の一歩（任意。「英単語20個」「走った」「飲まなかった」）。

| 出来事 | だるまに起きること | 決まり |
| --- | --- | --- |
| 開眼 | 左目（向かって右）を指でなぞって入れる | 1筆で済む。右目を先に入れる地域もあるので、設定で左右を選べる |
| 今日の一歩 | 1筆入る（0.5秒の描画演出） | 1日1回。その日のうちは取り消せる。筆の順番は眉→ひげ→腹の文字の縁→衣の模様 |
| 節目 | 見た目が一段変わる | 7日：眉が揃う、21日：ひげが揃う、50日：腹の文字が金になる、100日：衣に金彩が入る。節目の日だけ共有を促す |
| 転ぶ | 記録のない日が1日あると、翌日のホームで横倒しになっている | 模様は減らない。転んだ日数は増えない（何日空いても1回の転び） |
| 起き上がり | 転んだあとの記録で起き上がり、台座に金の筋が1本増える | 筋は累積。「起き上がり○回」を筆の数と並べて表示する。転ぶほど台座が金になる |
| 休み券 | 転ばない | 月に2枚（ookura_streak）。前日までに「明日は休む」と宣言したときだけ。当日や事後には使えない |
| 両目（満願） | もう片方の目を入れ、「満願 日付」が入って棚へ | 達成は本人の宣言。期限があるだるまは、期限日に1回だけ「叶った？」と聞く |
| 納める | 片目のまま棚の「納め」段へ | 削除ではない。同じ目標で「ひと回り大きいだるま」を作れる（年ごとに大きくしていく習わしにならう）。棚には大きさの違うだるまが並び、粘りの履歴が見える |

連続日数は主役にしない。表示はするが、切れたときに「0日」を大きく出さない。主役は累計の筆の数と起き上がり回数で、どちらも減らない。ストリーク復活を買わせるのではなく「転んでも減らない」設計で受け止める。

色と文字：

- 色は12色（赤を既定に、白・黒・黄・緑・青・紫・桃・金・橙・紺・茶）。色の意味は産地や店で違うので、アプリでは断定せず「一言の由来」だけ添える
- 腹の文字は縦書きの毛筆体。「合格」「必勝」「家内安全」「無病息災」のプリセットと自由入力
- 見た目は、色・文字・筆の数・起き上がり回数・大きさの段階から CustomPainter で描く。眉とひげの線はだるまの seed を種にした決定的な乱数で少し揺らし、同じだるまはいつも同じ顔になる。画像素材は持たない

## 6. ウィジェットと受験カウントダウン

検索ギャップ調査で首位アプリの不満だった4点（0時に進まない、通知の日数が固まる、試験を1つしか載せられない、設定の不具合）を、初版ですべて潰す。

| 種類 | 表示 | 備考 |
| --- | --- | --- |
| iOS 小 | だるまと今日の一歩の有無（未記録は薄い輪郭） | タップで記録画面へ直行 |
| iOS 中 | だるま、目標名、本番までの残り日数、次の通過点、筆の数、起き上がり回数 | 試験を1つしか載せられない不満への答え |
| iOS ロック画面 | 円形：残り日数、横長：目標名と残り日数 | 受験生が最も見る場所 |
| Android 小・中 | iOS と同じ内容 | home_widget＋Glance |

- 0時更新：WidgetKit の Timeline に今後14日分のエントリを前もって生成し、各日の0時（端末のタイムゾーン）で切り替える。アプリを開かなくても日数が進む。Android は AlarmManager の0時更新に加え、翌日分の表示を前日のうちに書いておき、Doze で更新が遅れても表示が狂わないようにする
- 日数の計算：本番の日の0時と今日の0時の差を日単位で数える。通知文の日数は、日ごとに本文を変えた14日分を予約し直すことで、配信時に正しい値になる（首位アプリの「残り288日のまま」を避ける）
- 複数の試験：だるま1体に本番1つと通過点最大3つ（模試、出願締切、二次など）を持てる。無料の1体でも受験の日程は全部載る。プラスでだるまを増やすと、ウィジェットに出すだるまを設定で選べる
- 試験日プリセット：JSON（id、名前、日付、区分、出典 URL、更新日）を同梱し、jsDelivr から更新分を取る。取得に失敗しても同梱版で動く。日程は公式発表を確認できたものだけ入れる（確認元は README）
- 記録はアプリ内でだけ行う。ウィジェットから直接は記録しない。「ウィジェットで便利になりすぎて開かれないアプリ」を避け、評価依頼と購入導線の機会を残す
- 初回の開眼の直後にウィジェット設置を案内する

## 7. 共有画像と拡散の設計

拡散の単位はストアリンクではなく、自分のだるまの画像1枚。だるま（大）、腹の文字、「開眼から83日・起き上がり3回」、満願ならその日付、小さなアプリ名を入れる。1080×1350 と 1:1 を Canvas から PNG にし、share_plus で共有シートへ。ストアリンクは画像にも本文にも入れない（リンク付き投稿は閲覧が減る）。

投稿の山は4つ。どれも「自分が入る」「比較軸がある」「引用で一言添えたくなる」を満たす。

| 山 | いつ | 画像 | 共有文の初期値 |
| --- | --- | --- | --- |
| 開眼 | 作った日。正月と新学期に集中する | 片目のだるまと目標名 | 「だるま、開眼。」 |
| 節目 | 7・21・50・100日 | 見た目が変わっただるま | 「50日目。起き上がり3回。」 |
| 両目 | 合格発表日・達成日。発表日は全員が同じ日に投稿する | 両目のだるまと満願の日付 | 「満願。」 |
| 年末の棚 | 12月下旬 | その年のだるまを並べた棚（プラス） | 「今年のだるま。転んだ回数、合計11回。」 |

- 比較軸は「起き上がり回数」。転んだ回数の多さを誇れるようにする
- 学校単位の口コミを狙う。受験生同士がだるまを見せ合うのが入口。配信者起点は狙わない
- 季節の背景（正月の金屏風、合格の桜、年末のお焚き上げ）をプラスで解放し、話題にする理由を定期供給する
- 共有の促しは上の4つの山のときだけ。毎日の記録のあとには出さない

## 8. データモデルと状態管理

スタックは既存ポートフォリオの標準構成（Flutter、Riverpod の Notifier、Drift、Freezed、go_router、CustomPainter、ARB は ja 先行で en キーを初版から）。共有パッケージは ookura_iap、ookura_settings、ookura_streak（休み券）、ookura_design、ookura_a11y。この環境には共有パッケージがないので、窓口（抽象クラス）だけ切って仮実装にしてある（README「共有パッケージの差し替え」）。

| テーブル | 主な列 | 備考 |
| --- | --- | --- |
| darumas | id, name（腹の文字）, color_id, eye_side, created_at, opened_on（開眼日）, deadline（null可）, deadline_name, deadline_preset_id, daily_action（null可）, status（active／completed／retired）, completed_at, retired_at, size_rank, parent_id（null可）, seed, asked_at_deadline | 現役は無料1体。parent_id は「ひと回り大きいだるま」のやり直し元 |
| milestones | id, daruma_id, name, date, preset_id（null可） | 通過点、だるまあたり最大3件 |
| checkins | id, daruma_id, date（端末のローカル日付、daruma_id とで一意）, kind（step／rest）, memo（30字）, created_at | 1日1件。取り消しは当日だけ |
| recoveries | id, daruma_id, fell_after（最後に記録した日）, rose_on（起き上がった日） | 金の筋の本数＝件数。転びは記録の空白から導けるが、筋を確定させるために保存する |

試験日プリセットは同梱 JSON で DB には入れない。設定（reminder、eye_side_default、widget_style、day_shift_hours など）は ookura_settings の窓口（`SettingsStore`）。Freezed のモデルは Daruma、Milestone、Checkin、Recovery、DarumaLook（描画仕様：色、文字、筆の数、筋の本数、目の状態、大きさの段階、転倒中か）、AppSettings、ExamPreset、WidgetSnapshot、BackupData。

導く値：筆の数＝step の件数、節目＝筆の数の閾値、残り日数＝本番の日−今日、転倒中＝最後の step より後に rest で埋まっていない日がある。日付はすべて端末のローカル日付で扱い、アプリに戻ったときと0時に今日を取り直す。

状態管理（Riverpod Notifier）：

- `settingsProvider`：設定。`todayProvider`：今日（0時のタイマーとアプリ復帰で進む）
- `bundlesProvider` → `shelfProvider` / `activeDarumasProvider` / `lookProvider(id)`：棚と、だるまごとの DarumaLook（core の `buildLook` 純関数）
- `createDarumaProvider`：作成フォーム→開眼→保存の一時状態
- `darumaActionsProvider`：今日の一歩の記録と取り消し、起き上がりの確定（recoveries へ追加）、休み券、満願、納め、JSON の書き出し・読み込み。保存のたびに `syncOutside` でウィジェットと通知をそろえる
- `ShareImageRenderer`：DarumaLook とテンプレから PNG（Canvas 直描き。画面に出ていなくても作れる）
- `WidgetSyncService`：App Group（iOS）と SharedPreferences（Android）へ WidgetSnapshot（DarumaLook と14日分のタイムライン）の JSON を書き、更新を要求する

だるまの描画：CustomPainter で、体（色）、顔（目の状態）、眉とひげ（筆が1筆ずつ増える）、腹の文字（縦書き）、腹の文字の縁、衣の模様、台座の金の筋、大きさの段階を描く。眉は鶴、ひげは亀という古くからの特徴を、形を写すのではなく自前の線で表す（「高崎だるま」は地域団体商標なので、名前をアプリやストア文に使わない）。横倒しは体を回転して描く。画像素材は持たずベクターだけにして、容量を小さく保つ。

## 9. 収益

無料＋買い切り、広告なし。習慣化は買い切りが成立したジャンルで、広告は評価とウィジェット中心の画面に合わない。受験生とその親が主な利用者で、広告は評価を下げる。

| 区分 | 内容 |
| --- | --- |

## 11. リスクと対策

| リスク | 対策 |
| --- | --- |
| 習慣化アプリの既存勢と比べられる | 多習慣トラッカーと競わず、「目標1つ＝だるま1体」の目標帳として検索語（受験カウントダウン、合格祈願、だるま）から入る。機能数ではなく儀式と見た目で差を出す |
| 受験カウントダウンの首位から客が流れない | スクリーンショット1枚目を「片目のだるま＋残り日数ウィジェット」にして違いを見せる。試験専用の首位がない Google Play を先に出す |
| メクマデ（日めくりカウントダウン）との類似で 4.3 になる | 主画面はだるま。メタデータは「だるま」「目標」「受験」を軸にし、カウントダウンの語はサブタイトルに留める。ウィジェットのコードは流用しても UI と文言は別物に |
| 「転んでも減らない」が緩すぎて張り合いがない | 転倒中は横倒しを見せて落ち着かない状態にする。起き上がり回数と筆の数を分けて表示し、連続日数も小さく出す |
| 縁起物・宗教的な表現 | 効能を謳わない。宗派の説明はしない。目入れは一般的な風習として説明し、地域団体商標の名前（高崎だるまなど）は使わない |
| ウィジェットのネイティブ実装の工数 | Dart 側（WidgetSyncService と14日分のタイムライン）を先に固め、iOS を先に作り、Android は小サイズから（docs/WIDGETS.md） |
| 受験シーズンに間に合わない | 12月中旬を iOS の締切にする。間に合わなければ受験訴求を落とし、「新年のだるま」訴求で1月1日に出す |
| 毛筆フォントのライセンス | Yuji Syuku（SIL OFL 1.1）の1書体に絞り、ライセンス全文を同梱。文字は画像化せずフォント描画（README「毛筆体フォント」） |
| 深夜の記録で日付がずれ、転んだ扱いになる | 端末ローカル日付で判定。仮置きは「0〜3時も当日」で、設定で「前日の記録」に切り替えられる |

## 13. 初版の実装で決めたこと

| 項目 | 決めたこと | 場所 |
| --- | --- | --- |
| 1日の境界 | `DayBoundary(shiftHours)`。仮置きは 0（0〜3時も当日）。設定で 3 にすると前日扱い | `lib/core/local_date.dart` |
| 転倒判定 | 最後の step（なければ開眼日）より後で今日より前に、rest で埋まっていない日が1日でもあれば転倒中。今日 step を記録すれば立つ。rest は空白を埋めるが、転んだ状態を直しはしない | `lib/core/fall.dart` |
| 起き上がり | 転倒中に step を記録した瞬間に Recovery を1件保存（fell_after＝最後の step の日、rose_on＝今日）。当日の取り消しで一緒に消える | `lib/state/daruma_actions.dart` |
| 筆の割り当て | 1〜7 眉、8〜21 ひげ、22〜50 腹の文字の縁、51〜 衣（上限なし）。節目は 7・21・50・100 筆 | `lib/core/strokes.dart` |
| 休み券 | 月2枚は「休む日」の月で数える。宣言は明日以降の日付だけ。本番の日より後は不可。その日が来る前なら取り消せる | `lib/core/rest_tickets.dart` |
| 残り日数 | 本番の日 − 今日（当日は 0、過ぎると負）。ウィジェットは今日から14日分を前もって計算 | `lib/core/countdown.dart` |
| 通知 | 14日分を日ごとの本文で予約し、保存・設定変更・日付の切り替わりのたびに予約し直す | `lib/core/reminder_planner.dart`, `lib/services/reminder_service.dart` |
| ひと回り大きいだるま | size_rank は 1 から 5 まで。親の段階＋1 | `lib/core/size_rank.dart` |
| 無料とプラス | 現役1体、色は id 0〜2（赤・白・黒）、テンプレは和紙と枠 | `lib/core/entitlements.dart` |
| 評価依頼 | 7日目の節目と両目の直後だけ。365日に3回まで | `lib/core/review_policy.dart` |
| id と seed | 128ビットの乱数の16進。seed は32ビット | `lib/core/ids.dart` |
| 描画 | 幅100×高さ125の箱で設計し、与えられた大きさに収める。横倒しは体の中心を軸に回し、台座は回さない | `lib/ui/daruma/daruma_painter.dart` |
| 毛筆体 | Yuji Syuku を family `NanakorobiBrush` で同梱。腹の文字と共有画像で使い、太字は指定しない（Regular のみの書体） | `lib/ui/theme.dart`, `assets/fonts/` |
