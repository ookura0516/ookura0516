## 概要と比較

作るのは、Webで1分遊べて、作ったものをリンクで渡せるアプリ4本です。ホシムスビ（星座づくり）、ネジマキ（オルゴール作曲）、ハナビシ（花火づくり）、マスメ（すごろくメーカー）。宣伝サイトが体験版を兼ね、受け取ったリンクはアプリがなくてもブラウザで開けます。3案のご依頼に対し、回答で4案とも選ばれたため4本とも設計しました。名前はすべて仮称です。

| 案 | ひとことで | Webで1分でできること | アプリを入れる理由 | 共有の形 | 需要の山 | 開発の目安 |
| --- | --- | --- | --- | --- | --- | --- |
| ホシムスビ | 記念日の夜空に自分の星座を結ぶ | 日付と町を選び、星をなぞって名前をつける | 空にかざすと自分の星座の位置がわかる。ポスター書き出し、ウィジェット | その夜の空ごと贈るリンク | 七夕 7/7、誕生日・記念日 | 4週＋Web1週 |

- 宣伝サイトは Cloudflare Pages に置く。Vercel の無料プランは非商用に限られるため外した
- 2027年2月14日まで新作を止める決まりは守る。設計は今行い、公開は2月15日以降にWebとストアを同時に行う

## 共通の仕組み

4本とも、宣伝サイト・体験版・受け取った作品を開くページを1つのサイトにまとめ、Cloudflare Pages の無料枠に置きます。作品の中身はリンクそのものに入れ、サーバーには保存しません（マスメの盤だけが例外）。運用費は月0円の見込みです。

（図：作品リンクの流れ · 4本共通 — Docs版を参照）

リンクを開いた人がその場で作って送り返すと、輪がもう一周します。アプリで作った作品も同じ形のリンクで送れます。

### サイトの構成（1アプリ1サイト）

| パス | 中身 |
| --- | --- |
| / | 宣伝と体験版。開いてすぐ触れる。下にストアへのボタン |
| /c/（作品の中身） | 受け取った作品を開くページ。マスメは /b/（盤のID） |
| /privacy | アプリごとのプライバシーポリシー。Playで共用のポリシーが否承認になったため、アプリ別に置く |
| /.well-known/ | iOSの Universal Links と Androidの App Links の設定ファイル |

アドレスは「案名.pages.dev」で始め、独自ドメインは反応を見てから決めます。

### 作品リンクの形式

- 作品のデータ（JSON）を圧縮し、URLに使える文字（base64url）にする。先頭に形式の版番号を付け、古いリンクも開けるようにする
- ホシムスビ・ネジマキ・ハナビシは、どれも数百字に収まる
- アプリとWebで同じ形式を使う。各アプリのリポジトリに spec/ を置き、形式の説明と照合用のサンプル（リンクと、それを開いた結果）を入れる。Dart と TypeScript の両方のテストがこのサンプルを読み、同じ結果になることを確かめる
- リンクを知っていれば誰でも見られる。作る画面にそう書き、公開の一覧や検索は作らない。作品ページは検索エンジンに載せない（noindex）

### リンクを貼ったときのプレビュー（OGP）

- /c/ のページは Pages Functions が返す。リンクの中身から作品名を取り出し、タイトルと説明文に入れる（例：「ふたりの星 — 2026年11月22日 東京の夜空」）
- 画像はアプリごとに数種類の静止画から選ぶ（色や季節）。Workers の無料枠は1回の処理が10ミリ秒のCPU時間までで、作品ごとに画像を描くと超えるおそれがあるため
- 作品ごとの画像は、共有が増えてから検討する（作った端末で画像を描き、R2に置く方式）

### アプリへの受け渡し

- アプリが入っていれば、/c/ のリンクはアプリで開く（Universal Links・App Links）
- 入っていなければ、ブラウザでそのまま作品を見せ、「アプリで続きを」ボタンを出す。ボタンは既存の /go/ 計測（Firebase の go\_hits）を通ってストアへ行く。src=web\_案名 で流入元を分ける
- インストール後に元の作品を自動で開く仕組み（後払いのディープリンク）は作らない。もう一度リンクを押してもらう

### 計測

- ページの閲覧数：Cloudflare Web Analytics（無料、Cookieを使わない）
- 体験の各段階：「始めた」「作り終えた」「リンクを作った」「リンクが開かれた」「ストアへ押した」の5つを、Pages Functions で D1 に日別に数える。個人は特定しない
- ストアへの流入：既存の /go/ 計測に合わせる。以前の実測では、外部からの流入は全体の0.2%だった。この比率を上げるのがこの計画の目的

### 費用

| 項目 | 使うもの | 費用 |
| --- | --- | --- |
| ページの配信 | Cloudflare Pages | 無料 |
| /c/ のページと計測 | Pages Functions | 無料枠：1日10万リクエスト、1回10ミリ秒まで |
| マスメの盤、計測の集計 | D1 | 無料枠：1日10万行の書き込み、500万行の読み取り |
| ドメイン | 案名.pages.dev | 無料（独自ドメインは未見積もり） |

無料枠の上限は日本時間の午前9時（UTCの0時）に戻ります。D1 は2026年9月1日から、上限を超えるとその日は問い合わせが失敗します。

### 4.3(a)（似たアプリの量産）対策

- 4本で雛形を共有しない。画面、部品、色、アイコンの作り方をアプリごとに変える。共通なのは作品リンクの考え方だけで、コードは別々に書く
- 中身の芯がそれぞれ違う。星の位置の計算、音の合成、花火の粒の動き、すごろくの進行。「〜風の画像を作る」型ではない
- 提出は月1本までにする。11月の方針「新作は月1〜2本」の下の側に合わせる
- 説明文とスクリーンショットはアプリごとに別に作る

### リポジトリと公開の手順

- 各アプリを今までどおり個別の非公開リポジトリにし、app/（Flutter）、web/（TypeScript と Vite）、spec/（作品の形式と照合サンプル）を並べる
- Webの公開は wrangler pages deploy で行う。Macからでも GitHub Actions からでもよい（Cloudflare のAPIトークンはリポジトリのシークレットに置く）

## 案1 ホシムスビ（星座づくり）

記念日の日付と町を選ぶと、その夜の本物の星空が出ます。星を指でつないで自分だけの星座を作り、リンクで贈ります。アプリではスマホを空にかざすと、今夜その星座がどこに出ているかがわかります。

### 勝ち筋

- 「あの日の夜空」は誕生日・結婚記念日・出会った日の贈り物になる。そこに「自分で結んだ星座」を足すと、世界に1つの作品になる
- 自分で星座を作れるものは、小さなWebアプリ1本しか見つからなかった。「ほしのかたち」は実在の星座を使ったパズルで、用途が違う
- 作って送るまで1分。受け取った人はブラウザだけで見られる。実際の空で探すにはアプリが要るため、体験からインストールへの理由が自然にできる

### 遊び方

1. 日付と町を選ぶ。町は一覧から選び、GPSは使わない
2. その夜21時の空が出る。時刻はスライダーで動かせる
3. 星をなぞって結ぶ。指が近づくといちばん近い明るい星に吸い付く
4. 名前（20字まで）と一言（60字まで）をつけて、保存するか送る

| 画面 | 中身 |
| --- | --- |
| 星座帳（ホーム） | 作った星座を日付順に並べる。今夜見えるものに印 |
| 空（作る） | 星空、時刻スライダー、結ぶ・戻す、公式88星座の線を薄く表示する切替 |
| 星座の詳細 | 名前、日付、町、一言、使った星の名前と距離（「この光は約80年前に出た」） |
| 空でさがす | カメラの映像に星座を重ね、画面の外なら矢印で向きを示す |
| 書き出し | リンク、画像、ポスターPDF |

### Web体験版

- トップ：今夜の東京の空がゆっくり回り、だれかの作った星座が線で描かれる。「1分であなたの星座を作る」ボタン
- 体験：遊び方の1〜4がそのまま動く。最後にリンクと画像（1080px、小さなロゴ入り）がもらえる
- 受け取ったリンク：その夜の空が出て、星座が1本ずつ線で結ばれ、名前と一言が出る。下に「自分も作る」と「アプリで空にさがす」
- Webでできないこと：星座帳への保存、空でさがす、ポスター

### アプリだけの機能

- 空でさがす：カメラ、コンパス、ジャイロで向きを出す。コンパスのずれは、月か明るい星に画面を合わせて直す
- ウィジェット：「今夜21時、ふたりの星は南東・高さ40度」。端末の中で計算し、1日1回更新
- 通知（任意・1日1回まで・初期オフ）：自分の星座が高く昇る夜、記念日の夜
- ポスター書き出し：A3・A2のPDF。日付、町、緯度経度、星座の名前を入れる

### 収益

- 無料：星座3つまで、リンクで送る、空でさがす、ウィジェット
- ホシムスビパス（月¥250・年¥1,500・買い切り¥2,400）：星座無制限、ポスターPDF、ロゴなしの高解像度画像、星座に長い物語を書くページ
- 空でさがすを無料に残すのは、これがアプリを入れる理由そのものだから。課金は「増やす」と「形に残す」に置く

### データと技術

- 星表：Yale Bright Star Catalogue 第5版（約9,100個、6.5等まで）を第一候補にし、アプリとWebに同梱する。公式88星座の線のデータも含め、作る前にライセンスを確認する
- 位置の計算：赤経・赤緯と恒星時から高度・方位を出す。歳差も補正し、前後100年を扱う。月と惑星は1.1で足す
- リンクの中身：日付、緯度経度（0.1度に丸める）、星の番号と線、名前、一言。圧縮して約200バイトで、サーバーには保存しない
- 照合：同じ日付と町なら、DartとTypeScriptで星の位置が0.01度以内でそろうことを、共通の照合データで両方のテストにかける

### リスクと対策

| リスク | 対策 |
| --- | --- |
| 「星に名前をつけて売る」商法と混同される | 「公式の名前ではなく、あなただけの呼び名」と画面と説明文に書く。星そのものは売らない |
| コンパスが数度から十数度ずれる | 月や明るい星で合わせる補正。矢印は「だいたいの向き」として見せる |
| 住んでいる場所がリンクからわかる | 町の一覧から選ぶ。緯度経度は0.1度（約11km）に丸める |
| 星表や星座線のデータに利用条件がある | 作る前に確認。使えなければ公式の星座線は自作する（88本、約1日） |

## 案2 ネジマキ（オルゴール作曲）

紙テープに穴を打つようにメロディを作り、画面のネジを指で回すとオルゴールの音で鳴ります。回す速さがそのままテンポになります。送ったリンクを開いた人も、ブラウザでネジを回して聴けます。

### 勝ち筋

- 「回すと鳴る」は説明がいらず、受け取った人が必ず触る。メッセージカードの代わりに、ホワイトデー・卒業・母の日に送れる
- 紙テープ式の手回しオルゴールは、15音と半音つき30音の安価な自作キットが通販で売られている。その紙テープを実寸で印刷できれば、画面の中だけで終わらない
- 競合は、音符を置く作曲アプリと、専用基板に曲を送る穴あけ再現アプリ。ネジを回して鳴らす操作と、ブラウザで聴けるリンクは見当たらなかった

### 遊び方

1. 縦に流れるテープ（横が音の高さ、縦が時間）のマスをタップして穴を打つ。打った瞬間にその音が鳴る
2. 右下のネジを指で円を描いて回す。速く回すと速く、止めると止まる
3. 曲名と宛名をつけて、保存するか送る

| 画面 | 中身 |
| --- | --- |
| 曲の棚（ホーム） | 作った曲ともらった曲。オルゴールの箱の絵で並ぶ |
| 穴あけ（作る） | テープ、音の並び（15音・30音）、拍の線、戻す、範囲の写し（繰り返し） |
| 聴く | 箱とネジだけの画面。回して聴く。自動で回す切替つき |
| 書き出し | リンク、カード画像（QRつき）、音声ファイル、通知音、紙テープPDF |

### Web体験版

- トップ：開くと箱とネジがあり、「回してみて」だけ書いてある。回すと「きらきら星」が鳴る
- 体験：15音・8小節までの穴あけと、回して聴く。最後にリンクがもらえる
- 受け取ったリンク：宛名と曲名の入った箱が出て、回すと鳴る。下に「返事を作る」と「アプリで長い曲を作る」
- iPhoneのマナーモードではブラウザの音が出ないことがある。対策は「データと技術」に書いた

### アプリだけの機能

- 手回しの手ごたえ：穴が歯を弾くたびに端末が小さく振動する
- 長い曲（最大約4分）と30音（半音つき）。中身の違う音色を数種（小さな箱、木の大きな箱、引き出しの中）
- 自作の曲を目覚ましと通知音に：iOSはアプリ内の通知音として登録（30秒まで）。Androidは着信音・通知音に書き出す
- 実物用の紙テープ印刷：市販の15音・30音のテープ幅と穴の間隔に合わせ、A4に実寸で印刷する。切って穴を開ければ本物のオルゴールで鳴る
- カード印刷：曲のQRコードを入れたメッセージカード。花束や贈り物に添える

### 収益

- 無料：15音・16小節まで、保存3曲、リンクで送る、もらった曲を聴く
- ネジマキパス（月¥250・年¥1,500・買い切り¥2,400）：長い曲、30音、音色、通知音・目覚まし、紙テープPDF、カード印刷、保存無制限

### データと技術

- 音：録音は使わず、金属の歯の音を合成する（基音と倍音からずれた倒音、減衰、弾く瞬間の小さな雑音）。音色の設定値をアプリとWebで共通にし、同じ音にする
- Web：Web Audio で、回した角度から次の音の時刻を少し先まで予約して鳴らす。iPhoneのマナーモード対策に Safari の音声セッションを「再生」にする。効かない端末では「マナーモードを切ってね」と出す
- アプリ：Flutter。音は低遅延の再生ライブラリで、合成した音を歯ごとに用意しておく
- リンクの中身：音の並びの種類、拍の数、穴の位置（ビットの並び）、曲名、宛名。15音・64拍で圧縮前120バイトほどで、サーバーには保存しない

### リスクと対策

| リスク | 対策 |
| --- | --- |
| 利用者が著作権のある曲を打ち込んで送る | 公開の一覧や検索は作らず、リンクは検索エンジンに載せない。同梱の曲は著作権の切れたものと自作曲だけ。要確認（未決事項） |
| 合成した音が「オルゴールらしくない」 | 実物の15音・30音を買って録音し、合成音と比べて設定値を詰める |
| 紙テープの規格が製品ごとに違う | 実物を測ってから寸法を決める。印刷前に「この線がちょうど5cm」の定規で拡大縮小を確かめる |
| 30音の実物は紙の音名表記と実際の音がずれることがある | 表記ではなく実測した音に合わせて並びを決める |

## 案3 ハナビシ（花火づくり）

菊や牡丹など日本の花火の型と色を組み合わせて「玉」を作り、夜空に打ち上げます。玉を並べると自分の花火大会になり、リンクを開いた人のブラウザでそのまま打ち上がります。名前の由来は花火師です。

### 勝ち筋

- 開いて5秒できれいなものが見える。宣伝サイトの体験版としては4案でいちばん強い
- 花火を作るアプリは英語のものが数本あるが、芯・変化・昇り曲導といった和花火の作り方に沿ったものは見当たらなかった
- 7〜8月の花火大会の季節に、「行けない人に花火を送る」「誕生日に花火を上げる」使い方ができる。2月15日に着工すれば、その季節に間に合う

### 遊び方

1. 型を選ぶ：菊、牡丹、冠菊（かむろ）、柳、椰子、千輪、蜂、型物（ハートなど）
2. 色と変化を決める：開いてから色が変わる順番、芯（内側の輪）を何重にするか、昇るときの尾
3. 打ち上げる。光ってから少し遅れて音が届く
4. 玉を時間の線に並べて花火大会にし、送る

| 画面 | 中身 |
| --- | --- |
| 玉の蒵（ホーム） | 作った玉を並べる。玉の名前は型と変化から自動でつく（例：八重芯変化菊） |
| 玉づくり | 型、色の順番、芯、昇り、大きさ。作りながら何度でも打ち上げて確かめる |
| 花火大会 | 時間の線に玉を置く。連発（スターマイン）、背景（川、海、町）、同梱の曲 |
| 外で上げる | カメラの景色の上に打ち上げ、写真と動画を保存する |
| 書き出し | リンク、縦型動画、写真 |

### Web体験版

- トップ：夜の川と町の絵。画面を触るとその場所に1発上がる。「自分の玉を作る」ボタン
- 体験：型8種のうち4種と色を選んで1発作り、最大5発までの小さな花火大会をリンクにできる
- 受け取ったリンク：「○○さんの花火大会」の幕が上がり、タップすると始まる（音を出すためにタップが要る）。終わったら「もう一度」「自分も作る」「アプリで景色に重ねる」

### アプリだけの機能

- 全ての型（20種以上）と、芯・変化・昇り曲導の重ねがけ
- 花火大会は60秒まで。同梱の曲に合わせて並べられる
- 外で上げる：カメラの景色に重ね、ジャイロで花火を空の同じ場所に留める
- 縦型動画の書き出し：SNSにそのまま載せられる「自分の花火」の動画

### 収益

- 無料：型8種、玉の保存5つ、花火大会5発まで、リンクで送る、外で上げるの写真
- ハナビシパス（月¥250・年¥1,500・買い切り¥2,400）：全ての型と重ねがけ、60秒の花火大会、動画書き出し（ロゴなし）、保存無制限

### データと技術

- 玉の中身：型、星の数、開く大きさ、色の順番と時間、芯の重さ、尾。玉は1つ約30バイト、花火大会は玉と打ち上げ時刻の列で、サーバーには保存しない
- 動き：星ごとに初速、重力、空気の抵抗、燃える時間を持たせる。乱数は玉ごとの種から作り、同じリンクなら誰が開いても同じ開き方にする
- Web：WebGLで光の粒を加算して描く。WebGLが使えない端末は Canvas2D で粒を減らす。音は Web Audio で合成し、距離に応じて遅らせる
- アプリ：Flutter。粒はまとめて描く命令（drawRawPoints や drawAtlas）で加算して描く。端末が重ければ粒を自動で減らす
- 動画書き出し：絵をコマごとに作り、iOSは AVAssetWriter、Androidは MediaCodec の小さな自前の実装で動画にする。FFmpegKit は2026年7月に配布が終わったので使わない

### リスクと対策

| リスク | 対策 |
| --- | --- |
| 強い点滅で光過敏の発作を起こすおそれ | 画面全体が光る演出を作らない。明るい点滅は1秒に3回までに抑え、「まぶしさひかえめ」を初期でオンにする |
| 古い端末で動きが重い、暖かくなる | 同時に出る粒の数に上限を設け、コマの遅れを見て減らす。低価格のAndroidで実測する |
| 実在の花火大会の名前や映像を使ってしまう | 大会名は使わず、背景は架空の川と町にする。型の名前は一般の用語だけ |
| 夏に需要が偏る | 年越しと誕生日を第2の山にする。「誕生日の花火」の見本を用意する |

## 案4 マスメ（すごろくメーカー）

仲間内のネタや思い出でマスを埋めた、自分たち専用のすごろくを作ります。盤のリンクを開けば、その場の1台のスマホやテレビですぐ遊べます。A3で印刷すれば紙でも遊べます。

### 勝ち筋

- 送別会、卒業、結婚式の二次会、同窓会、家族の正月では、「自分たちのすごろく」が余興になる。幹事はテンプレとお題の山札で15分で作れる
- 直接の競合「スーパーすごろくメーカー」は、保存が3つまでで、最大7人のマルチプレイを売りにしている。こちらは写真マス、お題の山札、印刷、テレビ映しで差をつける
- Web体験版は「見本の盤で遊ぶ」がそのまま宣伝になる。受け取った盤はインストールなしで遊べるので、参加者全員がアプリを入れる必要がない

### 遊び方

1. テンプレを選ぶ：送別会、結婚式の二次会、同窓会、家族旅行、お正月
2. マスを埋める：「○○さんの口ぐせをまねる」「3マス進む」「1回休み」など。自作のお題300枚の山札から引ける
3. 参加者の名前と駒を決めて遊ぶ。1台を回すか、テレビに映す
4. 盤をリンクで送るか、印刷する

| 画面 | 中身 |
| --- | --- |
| 盤の棚（ホーム） | 作った盤ともらった盤 |
| 盤づくり | マスの文字、種類（進む・戻る・休み・ワープ・分かれ道・お題）、写真、並べ方 |
| 遊ぶ | 盤、駒、サイコロ、お題カード。横向きにするとテレビ映し用の大画面 |
| 書き出し | リンク、印刷用PDF（A3、1枚、またはA4を2枚貼り合わせ） |

### Web体験版

- トップ：見本の盤「会社員あるあるすごろく」（20マス）がそのまま遊べる。2〜4人、1台を回して5分ほど
- 体験：12マスまでの盤を作ってリンクにできる
- 受け取ったリンク：盤がそのまま開いて遊べる。終わると「自分たちの盤を作る」「アプリで写真マスを足す」

### アプリだけの機能

- 写真マス：思い出の写真をマスに貼る。写真は端末の外に出さず、アプリでのプレイと印刷だけに使う
- 100マスまでの大きな盤、分かれ道、ワープ
- 印刷用PDF：コンビニのネットプリントでそのまま印刷できる大きさと余白にする
- サイコロを振るときの振動、お題カードをめくる演出

### 収益

- 無料：盤1つ（30マスまで）、リンクで送る、遊ぶ
- マスメパス（月¥250・年¥1,500・買い切り¥2,400）：盤無制限、100マス、写真マス、印刷用PDF、お題パック、大画面の飾り
- 幹事は一度きりの利用が多いため、月額の解約が早いと見込む。その分、買い切りと年額を強めに見せる

### データと技術

- 盤は文字が多い（30マス×20字で圧縮前約2KB）。そのためマスメだけは中身をリンクに入れず、Cloudflare D1 に盤のJSONを置いて、8文字のIDでリンクにする（/b/のあとにID）
- D1 の無料枠は1日10万行の書き込みと500万行の読み取り。盤の保存は1回1行なので十分。上限を超えるとその日は保存できないため、保存できないときの表示を用意する
- 盤は最後に開かれてから1年で消す。作った人は、端末に保存された削除用の鍵で消せる
- ゲームの進行は端末の中で完結する。各自のスマホを手元のサイコロにする同時プレイは1.1の候補で、Durable Objects が無料枠で使えるかを作る前に確かめる
- Web：TypeScriptとHTML・CSS（盤は平面で足りる）。アプリ：Flutter

### リスクと対策

| リスク | 対策 |
| --- | --- |
| 盤の文字に悪口や個人情報が入る | 公開の一覧は作らず、リンクを知っている人だけが見られる。通報の窓口と、作った人による削除を用意する |
| 直接の競合がある | 写真、印刷、テレビ映し、テンプレで差をつける。先方の強み（7人のマルチプレイ）は追わない |
| 使われる時期が偏る | 3月（送別・卒業）、GW、年末年始に合わせてテンプレとお題を足す |
| 既存のマワソビと似て見え、審査で量産と取られる | 画面構成と部品を流用しない（共通の仕組みの4.3(a)対策を参照） |
